# QQ 空间说说知识库

把 QQ 空间的全部历史说说（含已删除后恢复的内容）变成一个**能对话的知识库**。

导出 → 建库 → 归纳人物画像 → 按人设对话。**回答必须有知识库依据**，
查不到就回答「当时我还不知道这是什么意思」，不编造。

这是一个 [Mini App](https://agent.minimax.cn/docs/miniapp/overview) 包，
可以在 MiniMax Code（MCode）里直接安装使用。

---

## 快速开始

### 1. 安装

**方式一：直接导入 zip**（推荐给不想折腾 git 的人）

下载 [`releases/qq-space-kb-1.6.2.zip`](releases/qq-space-kb-1.6.2.zip)，
在 MCode 里安装 Mini App 时选择这个包。

**方式二：clone 后本地安装**

```bash
git clone https://github.com/Yzero123/qq-space-kb.git
# 把 qq-space-kb/ 目录作为 Mini App 安装，或复制进 ~/.minimax/plugins/
```

### 2. 导出你自己的说说

在 MCode 里对 Agent 说：

> 打开我的 QQ 空间说说知识库，导出历史说说并建库。

会弹出一个 QQ 空间浏览器窗口，**你用手机 QQ 扫码**完成登录（这一步只能你本人做），
然后抓取全量说说、评论、点赞、定位和图片。抓取过程很慢（每页间隔 20 秒，每 10 页休息 3 分钟），
这是为了降低风控，别催它。

> **全程只需要扫这一次码。** 导出和回溯共用同一个常驻浏览器，登录态一直挂着。
> ⚠️ **别关掉那个浏览器窗口**——QQ 空间的登录态是会话 cookie，窗口一关就失效。
>
> ⚠️ **抓取期间不要切换 QQ 客户端账号**，有账号冻结风险。
> **浏览器被关掉就是你要中止**——程序不会自动重开。断点会留着，再点一次「开始导出」从断点续上。

### 3. 建库 + 对话

页面上依次点「构建知识库」→「生成人物画像」→「开始对话」。
「构建知识库」按钮就在「导出与建库」面板里、紧挨着「开始导出」；知识库建好后它会变成
「重新构建知识库」。顶部状态栏显示的是**现在能不能聊**，不是上一次操作停在哪一步——
导出流程跑完把阶段置回「待开始」之后，只要知识库还在，它仍然显示「知识库就绪」。

建库时会**自动生成一份统计底座画像**（纯统计，零成本零编造），点「生成人物画像」再让大模型
把它润色成有时间线、有社交圈、有性格的叙述。**建议先填「人设」**，决定 bot 用什么语气说话。

## 核心能力

| 阶段 | 动作 | 结果 |
|---|---|---|
| ① 导出 | 手机 QQ 扫**一次**码，Agent 驱动抓取全量说说 | `messages.json`（含评论/点赞/定位/图片） |
| ② 建库 | 两路数据按说说 ID 合并去重，切明细块与年度画像块 | 可检索的知识库 + 索引 |
| ③ 人物画像 | 归纳时间线、社交圈、说话方式、性格 | 一份「我是谁」底色，注入每轮对话 |
| ④ 对话 | 先检索，检索不到直接回固定话术；命中才让模型基于资料作答 | 有依据的回答，附来源 |
| ⑤ 直接在对话里用 | MCP 工具 + 技能 + 人设子代理，不开页面也能问知识库 | 同样的接地规则，代码兜底 |
| ⑥ 看分布 | 年份分布看板：KPI 四卡 + 逐年构成堆叠柱图 + 紧凑明细表 | 数据密集期与回溯集中期一眼可见 |

几个设计上花了力气的地方：

- **全程只扫一次码**。QQ 空间的 `uin` / `p_skey` 是会话 cookie，浏览器一关就没了——
  早期版本「导出开一个浏览器 → 抓完关掉 → 回溯再开一个浏览器」，于是每一步都要重新扫码。
  现在把浏览器变成**独立长驻进程**（运行器自己起系统 Chrome，带调试端口和持久化 profile），
  导出和回溯都通过 CDP 挂上去复用同一份登录态。
  关键机制（已实测）：`connectOverCDP()` 后调用 `browser.close()` **只断开客户端，Chrome 进程和调试端口都还活着**。
- **已删除说说的回溯**。优先读本机归档库，没有就走互动中心的历史消息接口——
  被点赞评论过的已删除说说会在那里留下痕迹。差集里混着「我评论过的别人的动态」，
  靠说说 ID 前 8 位（小端 u32 = 作者 QQ 号）区分作者，不是本人的丢掉。
- **没正文也要留痕**。已删除的卡片常常只剩时间戳和 `cell_id`，
  但发布时间能由 ID 反解出来，「发过、什么时候发、被谁互动过」本身就是真实知识。
- **对话脱离 HTTP 请求**。宿主会在请求超时后掐断连接，挂在请求里的模型回合会被一起杀掉。
  导出、画像、对话三处耗时操作统一是「登记任务 + 立即返回 + 轮询状态」。
- **接地校验分两层**。硬红线管具体事实（日期 / 数字 / 外文专名 / 引介人名），
  措辞重合度只兜「整段都在编」。中文口语里虚词天然不重合，阈值定太紧会把
  **有据可依**的回答误杀成固定话术——那看起来像「知识库里没有」，其实是有。
- **MCP 服务器不调大模型**。检索、统计、接地校验全是确定性计算，措辞生成交给宿主模型。
  「知识库里没有的不许编」因此由代码兜底，而不是靠提示词自觉——提示词会漏，校验器不会。
  MCP 与页面共用同一套检索与校验逻辑（`miniapp/node/kb.mjs`），两处不会漂移。
- **可视化是用户自有的派生技能**。协议 `mavis.widget.v1`，`mode: forked`，
  拷贝了完整的 GenUI 基础并记录来源摘要。它不自己取数，只消费业务流已经算好的统计；
  数据不足或接地校验判「知识库里没有」时一律走文字版。

细节和踩过的坑见 [`qq-space-kb/README.md`](qq-space-kb/README.md)（包内文档）
和 [`QQ空间说说知识库方案.md`](QQ空间说说知识库方案.md)（方案与工程复盘）。

```
qq-space-kb/

└── tests/
    ├── test.mjs                 # 110 项回归断言
    ├── export-session.mjs       # 「一次扫码」回归：会话管理器 / 编排器 / 接线 / 页面
    ├── mcp-smoke.mjs            # MCP 服务器冒烟测试
    ├── visualizer-static.mjs    # 可视化样例静态审查
    └── plugin-package.mjs       # 插件包结构校验

qq-kb-pipeline/                   # 早期 Python 参考实现（合并/切块/摘要 + AstrBot 接入）
```

Node 侧只用内置模块，**没有 npm 运行时依赖**；页面不加载任何远程资源。

## 关于隐私

**这个仓库不含任何个人信息。**

真实数据全部落在宿主注入的 `dataDir`（`raw/`、`kb/`、`state.json`），**不在仓库里**。
仓库内只有代码、文档、**合成**的演示数据和自绘图标。

自检结果（用真实数据展开成逐片段指纹后回扫仓库）：

| 检查项 | 结果 |
|---|---|
| 真实 QQ 号（112 个，各种写法） | 0 残留 |
| 真实说说 ID（90 个，可反解出 QQ 号） | 0 残留 |
| 真实长数字（时间戳 / 赞数等） | 0 残留 |
| 真实互动昵称（36 个） | 0 残留 |
| 真实正文 / 评论 / 地名的 4 字滑窗（766 个） | 0 残留 |
| 混合字符 8 字窗口（245 个） | 0 残留 |
| 本机绝对路径、用户名、宿主数据目录路径 | 0 残留 |

> 写测试或文档时**不要用真实账号的 cell_id、说说正文、好友昵称**——
> 哪怕只是一个 cell_id，也能反解出你的 QQ 号。
> 仓库里的样例一律按 `moodId()` 同样的编码规则现场合成。

你的真实数据只在本机，**别把 `dataDir` 一起分享**。

## 开发

```bash
cd qq-space-kb
node tests/test.mjs              # 110 项断言
node tests/export-session.mjs    # 48 项断言：一次扫码（会话管理器 / 编排器 / 接线 / 页面）
node tests/mcp-smoke.mjs         # MCP 服务器冒烟：真启动、真发 JSON-RPC、真调五个工具
node tests/visualizer-static.mjs # 可视化样例静态审查：信封、主题 token、安全、载荷
node tests/plugin-package.mjs    # 插件包结构校验：清单、路径、包体积、frontmatter、凭证

cd ../qq-kb-pipeline
python3 tests/make_fixtures.py             # 生成合成 fixture（含归档库 sqlite3）
python3 tests/test_pipeline.py             # 41 项断言
```

回归测试用 mock Agent 启动真实 Node 服务、走真实 HTTP 路由，
重点验证「知识库没有就不猜」这条硬规则。
