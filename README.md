# 人生档案

把你在社交平台发过的那些东西——QQ 空间历史说说（含已删除后恢复的内容）、
自己发的微信朋友圈动态、在别人朋友圈下留的言、点过的赞——变成一个**能对话的知识库**。

导出 → 建库 → 归纳人物画像 → 按人设对话。**回答必须有知识库依据**，
资料不足以回答就回答「当时我还不知道这是什么意思」，不编造。

这是一个 [Mini App](https://agent.minimax.cn/docs/miniapp/overview) 包，
可以在 MiniMax Code（MCode）里直接安装使用。

> 当前版本 **v3.0.1**。
> **第一次看这个项目**（尤其是来审核的）：从 [`交接说明.md`](交接说明.md) 入手——
> 那里有代码地图、测试清单、关键口径、脱敏机制和给审核者的检查清单。
> 完整版本历史见 [`CHANGELOG.md`](CHANGELOG.md)；
> 想回退到任意旧版，见 [版本历史与回退](#版本历史与回退)。

## 快速开始

### 1. 安装

**方式一：直接导入 zip**（推荐给不想折腾 git 的人）

下载 [`releases/life-archive-3.0.1.zip`](releases/life-archive-3.0.1.zip)，
在 MCode 里安装 Mini App 时选择这个包。

> 想要旧版？[Releases 页面](https://github.com/Yzero123/life-archive/releases)有全部历史版本的 zip。

**方式二：clone 后本地安装**

```bash
git clone https://github.com/Yzero123/life-archive.git
# 把 life-archive/ 目录作为 Mini App 安装，或复制进 ~/.minimax/plugins/
```

### 2. 导出你自己的说说

在 MCode 里对 Agent 说：

> 打开我的 人生档案，导出历史说说并建库。

会弹出一个 QQ 空间浏览器窗口，**你用手机 QQ 扫码**完成登录（这一步只能你本人做），
然后抓取全量说说、评论、点赞、定位和图片。抓取过程很慢（每页间隔 20 秒，每 10 页休息 3 分钟），
这是为了降低风控，别催它。

> **全程只需要扫这一次码。** 导出和回溯共用同一个常驻浏览器，登录态一直挂着。
> ⚠️ **别关掉那个浏览器窗口**——QQ 空间的登录态是会话 cookie，窗口一关就失效。
>
> ⚠️ **抓取期间不要切换 QQ 客户端账号**，有账号冻结风险。
> **浏览器被关掉就是你要中止**——程序不会自动重开。断点会留着，再点一次「开始导出」从断点续上。

### 3. 建库 + 对话

页面上依次点「构建知识库」→「生成人物画像」→「开始对话」。
「构建知识库」按钮就在「导出与建库」面板里、紧挨着「开始导出」；知识库建好后它会变成
「重新构建知识库」。顶部状态栏显示的是**现在能不能聊**，不是上一次操作停在哪一步——
导出流程跑完把阶段置回「待开始」之后，只要知识库还在，它仍然显示「知识库就绪」。

建库时会**自动生成一份统计底座画像**（纯统计，零成本零编造），点「生成人物画像」再让大模型
把它润色成有时间线、有社交圈、有性格的叙述。**建议先填「人设」**，决定 bot 用什么语气说话。

> v1.7.0 起，对话**不再**是「检索命中 → 复述几段原文」。
> 整个知识库会作为 prompt 交给宿主大模型，检索只负责给它找资料：
> 命中给明细，落空自动升级成全库速览。回答怎么组织、怎么串、怎么口语化，交给模型；
> 事实红线只负责拦住编造的日期和数字，模型自己说不知道时才回固定话术。

## 核心能力

| 阶段 | 动作 | 结果 |
|---|---|---|
| ① 导出 | 手机 QQ 扫**一次**码，Agent 驱动抓取全量说说 | `messages.json`（含评论/点赞/定位/图片） |
| ② 建库 | 两路数据按说说 ID 合并去重，切明细块与年度画像块 | 可检索的知识库 + 索引 |
| ③ 人物画像 | 归纳时间线、社交圈、说话方式、性格 | 一份「我是谁」底色，注入每轮对话 |
| ④ 对话 | 知识库整体当 prompt 交给宿主大模型；检索只负责找资料，模型负责说话 | 有依据、答得灵活的回答，附来源 |
| ⑤ 直接在对话里用 | MCP 工具 + 技能 + 人设子代理，不开页面也能问知识库 | 同样的事实红线，代码兜底 |
| ⑥ 看分布 | 年份分布看板：KPI 四卡 + 逐年构成堆叠柱图 + 紧凑明细表 | 数据密集期与回溯集中期一眼可见 |
| ⑦ 朋友圈（2.0 起，**可选**） | 导入你自己发的微信朋友圈历史动态 | 同一个知识库多一个来源；画像多出朋友圈专属维度，并给出「两个平台的表达差」 |
| ⑦′ 朋友圈互动（2.1 起，**可选**） | 连**你在别人朋友圈下留的言**、**你点过的赞**一起导入 | 画像多出「我最常回复谁」「我的留言风格」「我收到的反馈」；好友原文只作上下文，不算进「我说的话」 |

几个设计上花了力气的地方：

- **全程只扫一次码**。QQ 空间的 `uin` / `p_skey` 是会话 cookie，浏览器一关就没了——
  早期版本「导出开一个浏览器 → 抓完关掉 → 回溯再开一个浏览器」，于是每一步都要重新扫码。
  现在把浏览器变成**独立长驻进程**（运行器自己起系统 Chrome，带调试端口和持久化 profile），
  导出和回溯都通过 CDP 挂上去复用同一份登录态。
  关键机制（已实测）：`connectOverCDP()` 后调用 `browser.close()` **只断开客户端，Chrome 进程和调试端口都还活着**。
- **已删除说说的回溯**。优先读本机归档库，没有就走互动中心的历史消息接口——
  被点赞评论过的已删除说说会在那里留下痕迹。差集里混着「我评论过的别人的动态」，
  靠说说 ID 前 8 位（小端 u32 = 作者 QQ 号）区分作者，不是本人的丢掉。
- **没正文也要留痕**。已删除的卡片常常只剩时间戳和 `cell_id`，
  但发布时间能由 ID 反解出来，「发过、什么时候发、被谁互动过」本身就是真实知识。
- **对话脱离 HTTP 请求**。宿主会在请求超时后掐断连接，挂在请求里的模型回合会被一起杀掉。
  导出、画像、对话三处耗时操作统一是「登记任务 + 立即返回 + 轮询状态」。
- **知识库整体当 prompt，检索只负责找资料**（v1.7.0 起的思路）。
  早先的版本是「检索没命中就根本不调模型，直接回固定话术」——问法一变就露馅：
  「我是个什么样的人」检索不到任何一条具体说说，于是 bot 只会说「不知道」，
  可知识库里明明有几十条有正文的记录，**它明明答得出来**。用户反馈就是两个字：蠢。
  现在检索落空时自动补上**全库速览**，把全库记录摊给模型让它自己判断；
  答得出来就答，答不出来才说不知道。
- **固定话术由模型自己说**。它手里有全库资料，它说不知道，说明库里确实没有——
  比检索闸门瞎猜准得多。代码只做归一化。
- **事实红线只管硬事实**。日期 / 数字 / 模糊量 / 外文专名 / 引介人名不许编，
  对照范围是**整个知识库**而不是本轮检索到的那几块。
  措辞重合度**不再**作为拒答条件——中文口语里虚词天然不重合，
  实测有据的口语转述 0.33、掺假的经历 0.17，两者根本分不开，
  拿它当闸门只会把**有据可依**的回答误杀成「不知道」。
- **数字认写法，也认区间**。模型把 `3261887` 写成「326 万」是四舍五入不是编造；
  中文里「五十多万」说的是区间（50 万到 60 万），库里有 543000 就该算数。
  但库里随便一个「50」不能给「50 万」背书——这规则松了红线就形同虚设。
- **宿主报「暂时不可用」要重试**。宿主在 Mini App 刚启动 / 运行时换代的那一瞬间
  会回 `AGENT_UNAVAILABLE`，它的定义是「什么都没开始，稍后重试即可」。
  不重试的话，起来后问的**第一句话**会直接报错，第二句又正常，像「偶发抽风」。
- **MCP 服务器不调大模型**。检索、统计、事实校验全是确定性计算，措辞生成交给宿主模型。
  「知识库里没有的不许编」因此由代码兜底，而不是靠提示词自觉——提示词会漏，校验器不会。
  MCP 与页面共用同一套检索与校验逻辑（`miniapp/node/kb.mjs`），两处不会漂移。
- **可视化是用户自有的派生技能**。协议 `mavis.widget.v1`，`mode: forked`，
  拷贝了完整的 GenUI 基础并记录来源摘要。它不自己取数，只消费业务流已经算好的统计；
  数据不足或接地校验判「知识库里没有」时一律走文字版。

和 [`人生档案方案.md`](人生档案方案.md)（方案与工程复盘）。

### 取数辅助脚本（仓库 `tools/`）

抓密钥这一步在 macOS 上有平台级硬门槛，脚本把踩过的坑都填好了：

| 脚本 | 作用 |
|---|---|
| `tools/wx-clone-capture.py` | **推荐路线**：用工具自带的一次性副本流程抓密钥，**不动官方安装、不用 sudo、不改系统设置** |
| `tools/wx-import-moments.mjs` | 无头入库：把导出的 JSON 走真实路由送进插件并打印验收结果 |
| `tools/wx-path-check.py` | 只读预判：检查签名 / 写权限 / 调试授权，给出「点获取会不会失败」的结论 |
| `tools/wx-prepare-copy.sh` | 把 `/Applications/WeChat.app` 换成自己的副本（旧过权限门办法，已被 AMFI 拒绝推翻，留档） |
| `tools/wx-restore-copy.sh` | 一键还原上面的副本 |
| `tools/real-instance-drill.mjs` | 在**真实 dataDir** 上跑一遍完整验收路径，跑完自动还原 |

**三种回退方式，按场景选：**

```bash
# 1. 只想要某个旧版的安装包
#    → Releases 页面下载对应 zip，在 MCode 里重新安装即可
#    https://github.com/Yzero123/life-archive/releases

# 2. 想把源码切回某个版本（改代码、做对比）
git clone https://github.com/Yzero123/life-archive.git
cd life-archive
git checkout v1.6.2          # 切到旧版
git checkout main            # 切回来

# 3. 想撤销某个版本（不动历史，安全）
git revert <commit-sha>      # 逐个撤销
```

> 历史版本的发布 zip 发布前做了**脱敏修补**（把从真实数据抄来的两处值换成合成值）。
> tag 指向的是**原始提交**，`git checkout v1.6.2` 能复现未修补的原始内容。

## 关于隐私

### 数据流：三层，别混成一句「只在本机」

> 这段是 v3.0.1 补的。之前这里写的是「你的真实数据只在本机」——
> **这句话是错的**：对话与生成画像时，知识库内容会作为 prompt 交给宿主 Agent 与宿主大模型，
> 那一步数据确实会离开插件进程。写清楚边界比写一句好听的话有用。

| 层 | 内容 | 去向 |
|---|---|---|
| **① 本地落盘** | 原始导出、统一记录、知识块、人物画像 | 只在宿主的 `dataDir` 下。**不进安装包、不进 Git 仓库**（有自动回扫把关，见下） |
| **② 宿主 Agent 调用** | 本轮对话用到的命中块、年度摘要、画像文本；**点「生成人物画像」时是全量记录** | 作为 prompt 交给宿主 Agent → 宿主大模型。**这一步数据会离开插件进程** |
| **③ 宿主服务端留存 / 训练** | 由宿主服务的配置与条款决定 | **插件既管不了、也不承诺**。以你所用宿主服务的条款为准 |

插件自己**不做**的事：

- 不把知识库内容发往任何第三方 HTTP 接口（除了你指定的数据源：QQ 空间、微信取数工具）；
- 不把 `dataDir` 写进日志、错误响应或页面。

**所以**：本地落盘是私密的；**模型调用那一步不是**。
如果你不接受「本轮内容会交给宿主模型」，就**不要点对话和生成画像**——
插件的检索、统计、接地校验全在本地跑，不调模型。


**这个仓库不含任何个人信息。**

真实数据全部落在宿主注入的 `dataDir`（`raw/`、`kb/`、`state.json`），**不在仓库里**。
仓库内只有代码、文档、**合成**的演示数据和自绘图标。

自检已经**脚本化**，不再靠手写关键词扫：

```bash
cd life-archive
node tests/privacy-scan.mjs
```

它从本机真实知识库**现算**指纹（QQ 号的十进制与各种 hex 编码、完整 cell_id、
**8 位 owner 前缀**、16 位前缀、说说链接、昵称、正文 4 字滑窗），
再回扫包内每一个文件、**仓库根目录的说明文档**、以及 `releases/` 下的每一个 zip。
脚本里**不写死任何个人信息**。

| 检查维度 | 性质 |
|---|---|
| QQ 号（十进制 / 大小端 hex） | 硬拦 |
| 完整 cell_id | 硬拦 |
| **8 位 owner 前缀**（说说 ID 前 8 位 hex = 空间主人 QQ 号的小端编码） | 硬拦 |
| 16 位前缀（owner + 精确时间戳） | 硬拦 |
| 说说链接、昵称、地点 | 硬拦 |
| 正文 / 评论 / 地名的 4 字中文滑窗 | 硬拦 |
| 聚合数字（赞数、时间戳） | **只提示不拦**——不是身份信息，且极易与代码常量撞车 |
| 本机绝对路径、用户名、宿主数据目录路径 | 硬拦 |
| **微信 wxid**（2.0 起）：本人账号标识（基名 + 带设备后缀）、好友 wxid、动态 ID | 硬拦 |
| **包内 wxid 字面量**（2.0 起）：`wxid_xxxxxxxx` 形状 | 硬拦。**结构性规则，与本机数据无关，永远生效**；明显是 `demo` / `example` 的合成值放行 |

> **踩过的坑（v1.7.1 修掉）**：v1.3.0 ~ v1.6.2 的文档注释里写着一条**真实说说 ID** 当示例。
> 当时的扫描用的是「带上下文」的关键词（`mood/<前缀>`），
> 而包里的裸 ID 没有 `mood/` 前缀——**整个漏掉了**。
> 教训：扫隐私必须用**裸标识符**，不能用带上下文的模式。
> 现在示例已换成合成的 `4e61bc00…`，历史发布包也做了同样修补。
>
> **同一类事故第二次（v2.0.0 修掉）**：2.0 方案文档里写着本机真实 wxid。
> 仓库是公开的，等于把账号标识公开了。
> 现在回扫范围扩到**说明文档**，并加了一条结构性规则：
> 包内出现 `wxid_xxxxxxxx` 形状的字面量直接判失败。
>
> 写测试或文档时**不要用真实账号的 cell_id、说说正文、好友昵称**——
> 哪怕只是一个 cell_id，也能反解出你的 QQ 号。
> 仓库里的样例一律按 `moodId()` 同样的编码规则现场合成。

**别把 `dataDir` 一起分享**——它装着你的原始数据与完整知识库。
