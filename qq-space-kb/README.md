# QQ 空间说说知识库 · Mini App

把你的 QQ 空间历史说说变成一个会说话、但**只依据你的真实记录作答**的聊天 bot。

---

## 它做什么

| 阶段 | 动作 | 结果 |
|---|---|---|
| ① 导出 | 打开 QQ 空间登录页，你用手机 QQ 扫码；Agent 驱动导出工具抓取全量说说 | `messages.json`（含评论/点赞/定位）+ 归档库快照（含已删除后恢复的内容） |
| ② 建库 | 两路数据按说说 ID 合并去重；切明细块与年度画像块 | 可检索的知识库 + 检索索引 |
| ③ 人物画像 | 建库时自动生成统计底座；可再让大模型润色成有性格的叙述 | 一份「我是谁」底色，注入之后每一轮对话 |
| ④ 对话 | 知识库整体当 prompt 喂给宿主大模型；检索负责找资料，模型负责说话 | 有依据、答得灵活的回答，附来源 |
| ②′ 朋友圈（2.0 起，**可选**） | 导入你自己发的微信朋友圈历史动态 | 同一个知识库多一个来源；画像多出朋友圈专属维度，并给出「两个平台的表达差」 |

**核心约束：回答必须有知识库依据。** 资料不足以回答就说「当时的我还不知道这是什么意思」，不编造。

人物画像不是装饰。bot 只复述检索结果会显得「蠢」：问「我是个什么样的人」时它没有可复述的记录。
画像让 bot 知道自己是谁，于是泛化类问题有依据可依，口气也才像同一个人。

v1.7.0 起，对话不再是「检索命中 → 复述几段原文」：**整个知识库都作为 prompt 交给宿主大模型**，
检索只负责给它找资料，回答怎么组织、怎么串、怎么口语化，都交给模型。
事实红线还在，只是从「闸门」变成了「体检」——答完再查有没有编造，而不是查不到就不让答。

## 安装

本包是标准 MiniMax Plugin（含 `miniapp.json` 声明与页面 / Node 两份运行载荷），有两种装法：

### 方式 A：交给 Agent 装（最省事）

把本包目录或 ZIP 交给 MiniMax Code 里的 Agent，说一句：

> 这是个成品 Mini App 包，帮我安装并打开。

Agent 会按成品包流程完成校验、发布和启动。

### 方式 B：手动放到插件目录

```bash
# 把整个插件目录（含隐藏的 .minimax-plugin）复制到插件目录，不要带外层作者目录
cp -R qq-space-kb ~/.minimax/plugins/qq-space-kb
```

然后**重启 MiniMax Code**，在插件列表里确认「QQ 空间说说知识库」已识别并启用。

### 前提条件

- MiniMax Code 桌面端（macOS / Windows），**本地会话**。云端、SSH、Remote Control 会话不会启动本机 Mini App。
- 插件详情里保持 **Agent 调用（session.run）** 打开。导出和对话都要用它。
- 无需预装任何依赖：Node 侧只用内置模块，导出工具由 Agent 在运行过程中自动 clone 和安装。

## 怎么用

### 三步走

1. **打开 Mini App**
   在 MCode 里打开「QQ 空间说说知识库」。页面上半部分是导出与建库，下半部分是对话。

2. **填 QQ 号 → 点「开始导出」**
   - 填你的 QQ 号。用于校验记录归属，并从说说 ID 反解原始发布时间，**强烈建议填**。
   - 会弹出一个 QQ 空间浏览器窗口，**用手机 QQ 扫码**完成登录。这一步只能你本人做。
   - **整个流程只需要扫这一次码**：导出和回溯共用同一个浏览器，登录态全程保留。
     页面上的「登录会话」卡片会实时告诉你浏览器还活着没、登录态在不在。
   - ⚠️ **别关掉那个浏览器窗口**。QQ 空间的登录态是会话 cookie，窗口一关就没了，
     下次就得重新扫。关窗口 = 你主动中止，程序不会自动重开。
   - 抓取过程慢速进行（每页间隔 20 秒，每 10 页休息 3 分钟），降低风控。
   - 期间 Agent 请求执行命令时，页面会出现授权卡片，点「允许一次」继续。
   - ⚠️ 抓取期间不要切换 QQ 客户端账号，否则有账号冻结风险。
   - **浏览器被关掉就是你要中止**，不会自动重开。断点会留着，再点一次「开始导出」从断点续上。

3. **点「构建知识库」→「生成人物画像」→「开始对话」**
   - 「构建知识库」按钮就在「导出与建库」面板里，紧挨着「开始导出」——
     知识库建好之后按钮会变成「重新构建知识库」。
   - 页面会显示说说总数、其中已删除后恢复的条数、覆盖年份区间、知识块数量。
   - **建库的同时就会自动生成一份「统计底座」画像**（纯统计，零成本零编造），
     对话立刻就有底色可用；再点一次「生成人物画像」，让大模型把它润色成
     有时间线、有社交圈、有性格的叙述。这一步在后台跑，页面会显示进度。
   - 建议先填「人设」，决定 bot 用什么语气说话。
   - 直接在下方对话框提问。

### 提问示例

| 问题 | 预期 |
|---|---|
| 2015 年我在忙什么 | 命中年度画像，给出有依据的回答 |
| 我有没有提过静安寺 | 命中明细块，引用具体那条 |
| 我是个什么样的人 | 走全库速览，把多条记录串成一段有性格的概括 |
| 那几年我过得怎么样 | 同上，按年度把那段日子串起来 |
| 2020 年我一共发了几条 | 照年度小结的条数答；答错会被事实红线拦下 |
| 特斯拉 Cybertruck 续航多少 | **「当时的我还不知道这是什么意思」**（模型自己说不知道） |
| 我当年买过特斯拉吗 | **「当时的我还不知道这是什么意思」**（模型手里有全库，它说没有就是没有） |

> 模型回合要几十秒。问完之后对话区会显示「正在想…」，等一会儿就出结果。
> 这是后台任务在跑，页面不会卡死；刷新页面也不会丢——结果存在服务侧。

### 微信朋友圈（2.0 起，可选）

QQ 空间是「回顾」，朋友圈是「当下」。两个数据源性格不同，叠起来画像才完整。
**这个数据源默认是关的**——不导入、不开启，1.0 的行为一个字都不变。

**怎么用**

1. 准备好一份**朋友圈导出 JSON**（见下一节）。把它放到面板「微信朋友圈」一栏显示的目录里，
   或者在路径框里手填完整路径。点「导入」——插件会自动扫桌面、下载、文档目录。
2. 导入后点「启用朋友圈」，再点上面的「重新构建知识库」。
3. 想退回纯 QQ 空间：点「停用朋友圈」→ 重新构建。知识库立刻回到 1.0 的样子。

**导入之后，画像里会多出来的东西**

| 维度 | 说明 |
|---|---|
| 发圈节奏 | 逐年条数、平均每年发多少 |
| 最密集的月份 | 哪个月发得最密 |
| 发布时段 | 常在早上/中午/下午/晚上/深夜的哪个时段发，占比多少 |
| 常出现的位置 | 朋友圈里最常出现的地点 |
| 媒体偏好 | 多少比例配了图、多少比例带视频、平均每条几张图 |
| 内容类型 | 文字 / 图片 / 链接 / 音乐 / 视频号 / 笔记 各占多少 |
| 互动最多的人 | 朋友圈里谁给你点过赞、评论过 |
| **两个平台的表达差** | 朋友圈平均多少字、多少比例配图；QQ 空间平均多少字、多少比例配图 |

最后一条是双源才看得到的结论——它能把「你在朋友圈话更短、但更爱配图」这种话说出来。

**硬规矩**

| 规矩 | 为什么 |
|---|---|
| **只取本人发的** | 好友的朋友圈不是「我发的」，进库等于让 bot 替别人说话 |
| **媒体只存链接与描述，不下载** | 图片视频走 CDN + 独立加密；而且微信 CDN 上约 58% 的旧图已失效，对画像收益有限 |
| **只读不写** | 不发布、不点赞、不评论朋友圈 |
| **插件不碰你的系统安全设置** | 不跑 LLDB、不关 SIP、不改任何系统配置。解密是外部工具的事 |

**「一条都没导入成功」是什么意思**

如果导出的文件里没有一条是你本人发的（比如导出的是别人的账号、或者账号标识不匹配），
插件会**直接告诉你**，而不是假装成功。可以在导入时手动填上你自己的账号标识（wxid）来对齐。

**数据从哪来**

插件只认「朋友圈导出 JSON」这一种输入，格式见
[`微信朋友圈数据契约-2.0.md`](https://github.com/Yzero123/qq-space-kb/blob/main/微信朋友圈数据契约-2.0.md)。
这个格式**刻意对齐 SIWX 的 JSON 导出**，所以：

- 用 **SIWX** 导出的 JSON → 直接放进去就能用，零转换；
- 用本包自带的取数工具导出的 JSON → 同样直接能用（它只认**已经解开**的 `sns.db`）：

```bash
# 看本机有哪些候选库、哪些已经解密
python3 miniapp/node/wx-export-runner.py discover

# 把已解密的库导成插件认得的格式
python3 miniapp/node/wx-export-runner.py parse --db <已解密的 sns.db> --out wechat_sns.json
```

> ⚠️ **macOS 上的实话**：微信朋友圈库是加密的，密钥只在运行中的微信进程内存里，
> 所以取密钥必须用调试器（LLDB）附加微信进程。**但要不要关 SIP，取决于你用哪个工具：**
>
> | 工具 | 要不要关 SIP | 你要做的 |
> |---|---|---|
> | **WeChatDataAnalysis 独立工具**（`WeDataKeyExtractor.app`） | **不用关**（官方文档明说「不移除隔离属性，不关闭 SIP/Gatekeeper」） | 给它「完全磁盘访问权限」；必要时给微信一次「开发者工具 → 单应用授权」；工具会**临时重签微信并自动恢复腾讯原版** |
> | **SIWX** | **要关**（官方文档明说「root / `sudo` 也不行」） | `csrutil disable` + 重启进 Recovery 再开回来 |
>
> 插件把这个动作整个**挪到了自己范围之外**——它不替你关 SIP、不替你重签微信、不替你跑调试器。
> 用什么方式导出由你决定，插件只负责把 JSON 收进来。

### 顶部状态栏说的是「现在能干什么」

状态栏和三个步骤条反映的是**磁盘上的真实状态**，不是上一次操作停在哪一步：

| 状态 | 含义 |
|---|---|
| 待开始 | 还没有可用的知识库 |
| 正在导出 / 正在构建 | 正在跑 |
| **知识库就绪** | 知识库已建好，可以直接对话 |
| 出错了 | 上一次操作失败了，原因写在状态行下面 |

导出流程跑完、服务端把阶段置回「待开始」之后，只要知识库还在，状态栏就仍然显示
**知识库就绪**——因为这时候确实能聊。

> 如果你在知识库建好之后又导出了一次，页面会额外提示「新导出的数据还没进知识库」，
> 点「重新构建知识库」刷新。

### 回答上的标签

每条 bot 回复左上角都会标出它属于哪种情况，别把两种失败混在一起看：

| 标签 | 含义 |
|---|---|
| 当时的我 | 有知识库依据，展开「依据 N 条知识库记录」能看到出处 |
| 当时的我 · 知识库里没有这条 | **模型自己说不知道**（手里有全库资料，它说没有就是真的没有） |
| 当时的我 · 回答含资料外的事实，已拦下 | 模型答了但出现了知识库里没有的日期 / 数字，答案被丢弃 |

后一种可以展开「查看被拦下的原话（未采用）」，看到模型本来想说什么。

> v1.7.0 起，来源标题会多一句「（检索没命中，已翻全库）」——
> 说明这轮是**把整个知识库摊给模型**才答出来的，不是只看了检索命中的那几条。

### 权限卡片

Agent 执行浏览器操作、跑命令行时需要你确认，页面会弹出授权卡片。点「允许一次」或「拒绝」，卡片会消失。拒绝不会中断整体流程，Agent 会收到「已拒绝」并自行决定下一步。

对话环节不会请求任何工具权限——模型只能看本轮给它的资料。

## 不开页面也能用：MCP 工具 · 技能 · 人设子代理

这个包同时是一个**带能力的插件**（v1.4.0 起）。不想开页面时，可以在 MCode 对话里直接用知识库。

### MCP 工具（server: `qq-space-kb`）

| 工具 | 作用 |
|---|---|
| `kb_stats` | 说说总数、已删除后恢复条数、覆盖年份、知识块数、画像来源、人设 |
| `kb_search` | 按问题检索原文，返回命中块 + 是否置信 + 人物画像 |
| `kb_records` | 按年份 / 恢复状态 / 关键词盘点原始记录 |
| `kb_profile` | 人物画像（性格、时间线、各年代表原文） |
| `kb_ground_check` | 接地校验：回答能不能发出去 |

**这个服务器不调大模型。** 检索、统计、校验全是确定性计算；措辞生成交给宿主模型。
这样「知识库里没有的不许编」由代码兜底，而不是靠提示词自觉——提示词会漏，校验器不会。

知识库数据目录的定位顺序：`QQ_SPACE_KB_DATA_DIR` 环境变量 → 插件安装布局
（`<dataDir>/plugins/qq-space-kb` → `<dataDir>/v2/plugin-data/liveboards/qq-space-kb`）→
扫描 `<dataDir>/v*/plugin-data/liveboards/qq-space-kb` 取最新可用的一份。

### 技能 `qq-space-kb`

把整套流程写成了可复用的操作规程：检索找资料 → 分层喂给模型（命中给明细、落空给全库速览）→
模型组织回答 → **事实红线体检** → 输出。红线不过就换固定话术，一个字都不多说。

### 可视化技能 `qq-space-kb-visualizer`

把 `kb_stats` 的年份分布画成看板：KPI 四卡 + 逐年构成堆叠柱图 + 紧凑明细表。
点某一年可以下钻追问那年的说说。

它**不自己取数**——数据全部来自业务流已经算好的 `kb_stats.yearDistribution`，
图上每个数字都能在知识库里找到出处。数据不足、用户要纯文字、或接地校验判定
「知识库里没有这条」时，一律走文字版，不出图。

可视化是用户自有的派生技能：协议 `mavis.widget.v1`，`mode: forked`，
拷贝了完整的 GenUI 基础（`references/genui-widget/`，5 个文件），
来源与摘要记在 `genui.json` 里。Creator 后续更新基础不会静默改动它。

### 人设子代理 `qq-space-kb:qzone-persona`

一个专属角色：以「过去的自己」的口吻说话。主 Agent 用 `task` 工具按
`agent_name: "qq-space-kb:qzone-persona"` 委派给它，它只带本插件的 MCP 与技能，
不会乱翻文件或乱联网。

> 子代理需要支持插件子代理的 MiniMax Code 版本；旧版本会忽略 `agents` 字段，
> 其余能力（MCP / 技能 / Mini App）照常可用。

## 回答是怎么被约束的

v1.7.0 的思路换过一次：**知识库整体作为 prompt 交给宿主大模型，检索只负责给模型找资料。**

早先的版本是「检索闸门 → 提示闸门 → 接地闸门」三道门：检索没命中就**根本不调模型**，
直接回固定话术。这套设计在「2015 年我在忙什么」这种问法上很好用，但换个问法就露馅了——
「我是个什么样的人」检索不到任何一条具体说说，于是 bot 只会说「当时的我还不知道这是什么意思」，
可知识库里明明有几十条有正文的记录，**它明明答得出来**。用户看到的反馈就是两个字：蠢。

现在改成三段：

### 1. 分层喂资料：命中给明细，落空给全库

对话先做 BM25 检索（中文按字符二元组切分，无需分词器）。然后按命中情况分层给模型：

| 层 | 内容 | 什么时候给 |
|---|---|---|
| 你是谁 | 人物画像（统计底座 + 大模型叙述） | 总是 |
| 人设 | 你自己写的那段设定 | 填了就给 |
| 年度小结 | 每年一条：条数、互动总量、话题、代表原文 | 总是 |
| 相关说说 | 检索命中的明细块 | 检索命中时 |
| **全库速览** | **每条记录一行「日期 · 正文摘录」，全库摊开** | **检索落空时自动补上** |

问句会先做**问法词归一化**：「什么」「怎么」「我」「在」这类问法词不进检索，
否则「2018 年我在忙什么」会被「我在忙」稀释掉分数，把明明存在的年份记录判成查不到。
归一化后若只剩一个年份，就按年份直接定位那一年的记录。

**检索落空不是「答不了」，而是「换一种喂法」。**
落空时把全库速览摊上去，模型自己看：这几十条里有没有能回答「我是个什么样的人」的东西？
有，它就答；没有，它就说不知道。这是「知识库里有就说有」和「知识库里没有就不装懂」之间唯一的分界。

### 2. 提示闸门：把规矩写进系统提示

系统提示固定 10 条，要点：

- 只说资料里有的事，资料外的时间 / 地点 / 人物 / 数字 / 事件一个不提；
- **资料不足以回答时，只输出那一句固定话术**，不解释、不客套、不追问；
- 回答像发朋友圈：1–3 句，短句、口语化、不说教；
- 不输出「根据资料」「根据知识库」这类元叙述；
- 历史内容一律用**过去时态**叙述（资料是过去留下的记录）；
- 「正文未能恢复」的说说，只能说它发过、什么时候发、被谁互动过，**不要猜它当时写了什么**；
- 尽量用资料里的原话和原词；
- 不必逐条复述，可以把好几条串成一段话；
- **条数、数量一律照【年度小结】里的数字抄，不要自己去数全库速览的行数**——数出来的会错，错的会被红线拦下。

每个问题都开一个**独立会话**，上一轮被判为编造的原话不会留在会话历史里污染下一轮。
连续性靠显式并入的知识库上下文维持（本轮命中的块 + 此前检索到的块，上限 12 块），不靠模型记忆。

对话里**禁用一切工具**：模型只能看本轮给的资料，不能上网、不能读文件、不能调 MCP。

### 3. 事实红线：答完再体检

模型回答后，Node 侧再体检一次。**任一硬红线不达标就丢掉模型答案，改用固定话术**：

| 检查 | 规则 | 性质 |
|---|---|---|
| 日期 | 答案里的年 / 年月 / 年月日 / 月 / 日，必须能在**整个知识库**里找到对应的那一天 | 硬红线 |
| 数字 | 答案里量级 ≥ 10 的数字（含中文数字，如「一万」）必须能在知识库里找到 | 硬红线 |
| 模糊量 | 「五十多万」按**区间**判：知识库里有个数落在 50 万到 60 万之间就算有据 | 硬红线 |
| 外文专名 | 答案里含大写字母的外文词（`iPhone`、`Instagram`、`Tesla`）必须在知识库里出现过 | 硬红线 |
| 引介人名 | 「认识了一个叫小美的朋友」——小美得是知识库里真有其人 | 硬红线 |

**对照范围是整个知识库，不是本轮检索到的那几块。**
早先只拿「本轮这几块」当对照，模型提到库里真实存在、但这轮没检索到的内容（比如 2022 年）会被误判成编造。
红线的职责是「库里有没有出处」，不是「这轮有没有提到过」。

**措辞重合度不再作为拒答条件，只留作展示。**
中文口语回答里虚词二元组（「那帮人」「倒是没少」）天然不重合，拿它当闸门会把
**有据可依**的回答误杀成固定话术——那看起来像「知识库里没有」，其实是有。
实测重合度分布：照资料原话转述 0.73，有据的口语转述 0.33，掺假的经历 0.17，纯编造 0.04——
有据的和掺假的根本分不开，拿它当闸门只会误杀。

日期检查做了**写法归一化**：资料里存的是 `2015-11-20`，模型常写成「2015 年 11 月 20 日」「2015年11月20号」，
这些认作同一件事；而「2015 年 11 月 21 日」这种真正对不上的会被拦下。

数字检查做了三件细致事：

- **剥掉 URL 和 `cell_id`** 这类长 hex 串。不剥的话，`cell_id`「…3c0500」里的「500」会被当成知识库里出现过的数字，于是「我欠了同学 500 块」这种编造能蒙混过关。
- **认同一个数的不同写法**。模型很自然会把 `3261887` 写成「326 万」，这是四舍五入不是编造，按 2% 容差判。
  但只有**本身就不小的**已知数才允许再放大一档——否则知识库里随便一个「50」都会让「50 万」蒙混过关（实测踩过这个坑）。
- **模糊量按区间判**。中文里「五十多万」说的是区间（50 万到 60 万），不是 500000 这个点。
  知识库里有 543000，模型写「五十多万」是**准确**的；按点值比会误杀一条有据的回答。

人设是用户自己写的，属于可信事实，也纳入接地上下文——免得模型复述人设里的年份时被误判成编造。

> 措辞级校验有天花板：中文没有分词器，「那帮人」和「小美」这类短语的可靠性有限。
> 所以除了让模型**照资料原话回答**（提示词里明确要求），画像里也直接带上各年的代表原文，
> 让它有原话可照——这既更像本人，接地校验也更有据。
> 仍然拦不住的是「大量真实转述里夹一句资料外的话」这种形态，
> 以及「数字有出处、但说的不是同一个口径」这种（总数被当成单条说说的互动数）。

### 4. 模型说不知道，才回固定话术

固定话术由**模型自己**说出来，不靠代码猜。

理由很直接：模型手里有整个知识库，它说「不知道」，说明库里确实没有；
比检索闸门瞎猜准得多。代码这边只做归一化：模型输出里含那句固定话术，
就记成 `model_declined` 并原样回给用户。

反过来，模型说自己知道、但红线查出来它编了（`ungrounded_factual_claim`），
照样拦下换固定话术——**「更灵活」不等于「更随意」**。

### 5. 宿主报「暂时不可用」时的重试

宿主在 Mini App 刚启动、或者运行时换代（重启 / 发布）的那一小段时间里，
Agent 桥会回 `AGENT_UNAVAILABLE`。宿主对它的定义是**「什么都没开始，稍后重试即可」**——
不是失败，也不是拒绝。

不重试的代价很实在：Mini App 起来后问的**第一句话**会直接报错，第二句开始又正常，
看起来像「偶发抽风」。实测（v1.7.0 自检）：刚启动后第一问撞上这个错误，
同一进程里的后三问全部正常——所以这确实是启动窗口，不是内容问题。

现在模型回合带退避重试（最多 3 次，间隔 0.8s / 1.6s）。
注意**不重试** `AGENT_OUTCOME_UNKNOWN`：那个码的意思是「回合可能已经跑了」，
重试会把同一个问题问两遍。

### 人物画像是怎么来的

画像分两层，**大模型只做润色，不负责事实**：

| 层 | 来源 | 作用 |
|---|---|---|
| 统计底座 | 纯确定性统计：跨度、年份分布、最活跃时期、常去地点、互动最多的人、反复话题、表达习惯、互动总量、最受欢迎一条、**各年代表原文** | 永远可用，零成本，零编造 |
| 大模型叙述 | 读完全量说说后写的时间线 / 社交 / 说话方式 / 性格 | 让 bot 有「像人」的叙述，而不是干巴巴的统计表 |

大模型写出的每一句都要过一遍事实校验（年份必须落在记录年份内、日期必须对得上、数字必须有出处）。过不了校验的句子直接剔除；站得住的句子不足 3 句、或占比低于一半，就**整段退回统计底座**。

所以画像永远不会是编的：最差情况是回到一份纯统计表。

**统计底座是建库时自动生成的**，不用等大模型——点一次「构建知识库」就有。
这一点不是可有可无：对话里少了人物底色，模型就没有「我是谁」可依，
泛化类问题（「我是个什么样的人」）会直接退化成「不知道」。

底座里特意带了**各年代表原文**（每年一条点赞最多的）。两个用处：
模型照着那一年的原话回答才像本人；事实校验靠的正是这些原话，
有原话可照，校验才有据。

**底座的口径必须和页面一致。** 报的是**全量**条数，并且区分「有正文」和「只有痕迹」：
「共 85 条说说（有正文 41 条，另有 44 条已删除、正文未恢复）」。
口径对不上，模型拿着画像说话就会跟页面对打架——它说 85 条、页面写 41 条，
用户分不清谁在骗人。

### 赞、评论、转发是三个数

知识库里这三个数分列，因为它们经常被混：

| 数 | 来源 | 备注 |
|---|---|---|
| 赞 | 桌面说说列表的 `a.qz_like_btn`（文本形如「赞(345)」） | 导出工具的 `like_count` **不是**这个数 |
| 评论数 | 工具输出的 `comment_count` | 评论**正文**当前抓不到，见下 |
| 转发数 | 工具输出的 `like_count` | 名字叫 like，实际是转发 |

混了这三个数，模型就会说错，而事实红线**拦不住**——它只查「这个数在不在库里出现过」，
不查「这个数说的是不是同一件事」。

**已知缺口**：现有说说的**评论正文**没抓到（`commentlist` 全空），只留了条数。
要抓正文得逐条展开「查看全部 N 条评论」，工作量大且容易撞腾讯 WAF 限流。
导出指令里已如实写明这是已知缺口。

## 时间是怎么来的

QQ 空间标准说说 ID 的前 16 位十六进制里藏着两个小端 u32：

```
b327e672 e295585b
└─ 空间主人QQ号 ─┘ └─ 原始发布时间戳 ─┘
```

所以即使一条说说的正文只在「点赞/评论残留」里还存在，**发布时间依然能精确还原**，时间轴不会因为删除而断裂。

每条记录都带时间精度标记，界面和知识块里都写得很清楚：

| 标记 | 含义 |
|---|---|
| 精确 | 源数据直接给出的发布时间 |
| 由说说ID反解 | 由说说 ID 还原得出 |
| 互动时间近似 | 只能拿到互动发生时间，是近似值 |
| 未知 | 完全不可考，不会编一个日期（仍会入库，正文照常可检索） |

## 导出工具

Agent 会自动准备下列工具之一，你也可以提前装好：

| 工具 | 仓库 | 特点 |
|---|---|---|
| get-qzone-history（首选） | github.com/Christina-zhou/get-qzone-history | Playwright 驱动真实浏览器扫码登录；字段干净；带断点续跑；macOS 下需把默认的 Windows `browserPath` 改成 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` |
| QQ-Zone-Restore-Archive | github.com/xiaosu19/QQ-Zone-Restore-Archive | Rust/Tauri 桌面端；**能从互动残留恢复已删除的说说**；库里是 SQLite，Agent 会转成 JSON |

两个都装的话效果最好：前者字段全（评论正文、点赞用户、定位），后者能捞回删掉的内容。

> 全量抓取耗时以小时计（默认 200 页 × 每页 20 秒 + 分段休息）。

### 导出是怎么被约束的

抓取脚本**不是**由 Agent 即兴写命令启动的。点「开始导出」时，Mini App 会把一个受控运行器写进数据目录（`export/qq_export_runner.py`），Agent 只需要调用它。运行器做四件事：

| 做什么 | 为什么 |
|---|---|
| 保证工具就位（缺就 clone，依赖缺就装） | Agent 不需要自己拼装环境 |
| **起一个常驻浏览器**（系统 Chrome + 调试端口 + 持久化 profile，独立进程组） | 浏览器是**登录态的载体**。由运行器自己起、自己留着，导出和回溯都挂上去复用它 |
| **把抓取脚本挂进独立进程组**（`start_new_session=True`） | 抓取要等扫码、以小时计。挂在一次前台工具调用里，工具调用一到时限就会连带把进程和浏览器杀掉——用户看到的就是「页面还没加载完就自动关闭」 |
| 把状态写进 `status.json` | Agent 轮询这个文件汇报进度，不用盯着长命令 |

**绝不自动重开浏览器。** 浏览器被关闭 = 用户主动中止，这时候自动重启只会不停弹窗、每次都要重新扫码。所以运行器里没有任何重跑循环：脚本退出就是退出，状态如实写进 `status.json`。断点留在 `result/` 目录里，用户再点一次「开始导出」就从断点续上。

导出指令里也把这条写成了铁律，并明确禁止 Agent 写 supervisor / 守护循环。

### 一次扫码是怎么做到的

QQ 空间的 `uin` / `p_skey` 是**会话 cookie**——只活在浏览器进程内存里，浏览器一关就没了，
持久化的 profile 也留不住。早期版本是「导出工具开一个浏览器 → 抓完关掉 → 回溯探针再开一个浏览器」，
于是**每一步都要重新扫码**，而且两个工具登录的还不是同一个页面。

现在把浏览器从「工具的附属品」变成**独立的长驻进程**：

```
                       ┌──────────────────────────────┐
   扫码一次 ─────────▶ │ 常驻 Chrome                   │
   （手机点确认）      │ --remote-debugging-port=0     │
                       │ --user-data-dir=<持久化 profile>│
                       └───────┬──────────────┬───────┘
                               │ CDP          │ CDP
                        ┌──────▼─────┐  ┌─────▼────────┐
                        │ 导出抓取    │  │ 回溯探针      │
                        │ --connect-cdp│  │ --cdp        │
                        └────────────┘  └──────────────┘
                          抓完不关它        复用同一份登录态
```

关键机制（已实测，Playwright 1.64 + Chrome 155）：用 `chromium.connectOverCDP()` 连上后调用
`browser.close()`，**只断开 Playwright 客户端，Chrome 进程和调试端口都还活着**。
所以导出工具跑完（它内部会 `browser.close()`）不会把常驻浏览器带走。

配套的三件事：

| 组件 | 作用 |
|---|---|
| `tools/qzone_session.js` | 常驻浏览器会话管理器：`start` / `status` / `stop` / `revisit`。`revisit` 是补救措施——某些跳转后服务端会把 QZone cookie 重新下发成空值，但 i.qq.com 的 SSO 还在，重新访问一次空间首页就能把 cookie 补回来，**不需要重新扫码** |
| `tools/qzone_feed_recover.js --cdp <端点>` | 回溯探针挂到常驻浏览器上，复用已有登录态。不传 `--cdp` 会退回老行为（自己开浏览器、还要再登一次），**别那样用** |
| `miniapp/node/export-runner.py` | 编排：起常驻浏览器 → 等扫码 → 抓取（带 `--connect-cdp`）。登录等待超时**不杀浏览器**，报错明确告诉用户「浏览器还开着，可以直接再扫一次，不用重启任何东西」 |

判断「登录好了」的判据始终是 **`uin` 有效 且 `p_skey` 长度 > 10**（和探针一致）：
只扫码不在手机 QQ 点「确认登录」，`p_skey` 不会下发，接口会一直回「需要登录」。

### 已删除的说说怎么回溯

按优先级找数据源，找不到就如实说明，**绝不编造**：

| 顺序 | 数据源 | 说明 |
|---|---|---|
| 1 | 本机归档库 | QQ-Zone-Restore-Archive 的 SQLite。macOS 在 `~/Library/Application Support/top.ehre.qzonearchive/qzone-archive.sqlite3`；找不到就全盘搜 `qzone-archive*.sqlite3` |
| 2 | 互动中心的历史消息 | 已删除但仍被人点赞评论的说说，会在历史消息卡片里留下痕迹：卡片带 `/mood/<cell_id>` 链接，而这个 cell_id 不在说说列表里。接口是 `user.qzone.qq.com/proxy/domain/ic2.qzone.qq.com/cgi-bin/feeds/feeds2_html_pav_all`（`count` 必须 ≤ 30） |
| 3 | 都没有 | 写一个空的 `{"dynamics": [], "feeds": []}`，页面显示「已删除后恢复 0」并**说明原因** |

页面统计下方的提示条会写清楚为什么是 0（例如「本机既没有 QQ 客户端缓存，也没有归档库」）。
这是数据源缺失，不是功能坏了——**没有被点赞评论过、已被服务端彻底清除的内容无法恢复**。

#### 正文没捞回来，也照样算一条

已删除的说说在互动卡片里常常只剩时间戳和 `cell_id`，正文预览未必还在。
但只要有 `cell_id`，发布时间就能由 ID 反解出来（`mood_cell_id_published_at`），
于是「发过、什么时候发、被谁赞过/评论过」本身就是能确证的事实——**这些条目会照常进知识库**，
正文位置写明「（这条说说已删除，正文未能恢复）」，模型被明确禁止去猜原文。

早期版本在「合并记录」和「切成知识块」两处都按「有没有正文」过滤，
结果明明捞到了 3 个 `cell_id`，界面却一直显示「已删除后恢复 0」。现在两处都不再丢弃这类记录。

#### 别人的动态不算「我的已删除说说」

互动卡片里混着「我评论过的别人的动态」。这类内容**本来就不在「我的说说列表」里**，
所以「历史消息有、说说列表没有」这个差集并不能直接当成「我已删除的说说」。

区分办法在 ID 里：QQ 空间标准说说 ID 的**前 8 位十六进制（小端 u32）就是作者 QQ 号**。
不是本人的就丢掉——收进来的话，bot 会声称自己发过根本没发过的内容，这比漏回溯一条严重得多。

同理，卡片上的 `data-time` 是**互动时间**而不是发布时间。
落盘时标上 `published_from: "interaction"`，真正的发布时间由 ID 反解；
反解不了就如实标成「互动时间近似」，不冒充精确时间。

#### 留言板上的留言也不算「我发过的说说」

互动中心的**留言板**卡片用一个叫 `richinfo` 的哨兵 `cell_id`——
它带的是**别人在我留言板上的留言**（"×××：以后生个娃儿……"），不是我说的话。

作者归属过滤救不了这一条：哨兵 ID 里没有作者 QQ 号可反解。
所以多加一道形态校验——**cell_id 必须长得像一条说说的 ID**：

| cell_id 形态 | 收不收 | 为什么 |
|---|---|---|
| 24 位十六进制（如 `b327e672…`） | 收 | 真说说 ID |
| `history-v2:` / `history-guestbook:` 开头 | 收 | 我们自己合成的占位 ID（正文没捞回来但发布时间能反解） |
| `richinfo` 之类的哨兵 | **不收** | 别人在留言板上的留言 |
| 空 / 其它形态 | **不收** | 不是一条说说 |

> 这条坑是真实踩出来的：旧知识库里就混进过一条 `richinfo`，
> 害得 bot 差点把朋友的留言当成「我说过的话」讲出来，
> 还把年份区间顶到了 2026（那条记录的 2026 只是**互动时间**）。
> 修掉之后记录数从 91 变 90、年份回到 2012–2022。

#### 现成探针（实测可用）

`tools/qzone_feed_recover.js` 是**已经跑通**的回溯探针，直接用就行，不用从零写。
它把这几个坑都处理了：没正文的条目也落盘、按作者过滤、每页增量落盘、
请求按需发（少打请求避开 WAF）、登录判定看 `p_skey` 而不是残留的 `uin`。

```bash
# 依赖：playwright（用导出工具自己的 node_modules）+ 系统 Chrome
cd <导出工具目录>
NODE_PATH=<导出工具目录>/node_modules node <包目录>/tools/qzone_feed_recover.js \
  --target-qq <QQ号> \
  --shuoshuo <导出产物 messages.json> \
  --out <数据目录>/raw/qzone_archive.json \
  --cdp http://127.0.0.1:<常驻浏览器端口> \
  --work-dir /tmp/qq-space-export-work --login-timeout 300 --max-pages 20
```

`--cdp` 指向导出阶段那个**常驻浏览器**的调试端点（写在 `status.json` 的 `cdpUrl` 里）。
带 `--cdp` 时探针**挂到那个浏览器上**，复用已经登录好的会话——**不用再扫一次码**，
跑完也不会把常驻浏览器带走（CDP 连接下的 `browser.close()` 只断开客户端）。

跑完把 `raw/qzone_archive.json` 放好，再点「构建知识库」即可。

> ⚠️ **不传 `--cdp` 会退回老行为**：探针自己开一个浏览器窗口，并且**需要你再扫一次码**
> （`uin` / `p_skey` 是会话 cookie，浏览器一关就没了，持久化的 profile 里留不住）。
> 导出的指令里已经写死了「必须带 `--cdp`」。
>
> 如果探针报「连不上常驻浏览器」，说明那个窗口被关掉了——重新点一次「开始导出」，
> 在新窗口里扫一次码即可（全程仍然只需一次）。
>
> 回溯还容易被腾讯 WAF 限流（HTTP 501 + `waf.tencent.com` 页面）——请求太密就会触发。
> 看到这个就等 30 秒以上再重试，翻页之间留 3–5 秒；一次回溯别反复重跑，跑得越勤冷却越久。
> 探针**每翻一页就落一次盘**，中途被拦掉时已拿到的卡片不会跟着一起丢。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面提示「未授予 Agent 调用权限」 | 插件详情里把「Agent 调用（session.run）」打开 |
| 导出卡在登录 | 需要你本人扫码，Agent 无法代替。**扫码后还要在手机 QQ 上点「确认登录」**，只扫不确认拿不到会话 |
| 又要重新扫码了 | 多半是**关掉了那个浏览器窗口**。QQ 空间的登录态是会话 cookie，窗口一关就失效。窗口还开着的话，在同一个窗口里补扫一次即可，不用重启任何东西 |
| 页面上的「登录会话」卡片变红 | 说明浏览器已经不在了，登录态失效。再点一次「开始导出」会重新拉起浏览器，扫一次码继续 |
| 浏览器被关掉了、页面自己又弹出来 | 旧版本的自动重跑。**当前版本不会**：浏览器被关 = 你中止了，不会自动重开。再点一次「开始导出」从断点续跑 |
| 页面还没加载完浏览器就自己关了 | 旧版本把抓取挂在一次前台工具调用里，工具调用到时限就把浏览器一起杀了。当前版本把抓取挂进独立进程组，不会被连带关闭 |
| 回溯探针报「连不上常驻浏览器」 | 常驻浏览器被关掉了。点一次「开始导出」重新拉起，扫码后回溯会自动复用它 |
| 导出被风控提示「使用人数过多」 | 调大间隔（`--page-wait-ms 20000 --segment-pause-ms 180000`），换个时间段再试 |
| 说说数明显偏少 | 归档库的深度扫描没跑完，或接口不再返回更早的数据；**没有被点赞评论过、已被服务端彻底清除的内容无法恢复**。页面会写明这次为什么是 0 |
| 回答总是「当时的我还不知道这是什么意思」 | 知识库是空的，或者模型手里有全库资料也没找到答案。先看统计里的说说总数 |
| 问「我是个什么样的人」也回固定话术 | 检索落空时会自动升级成全库速览，正常应该答得出来。正常不该发生；先确认知识库非空、统计底座已生成 |
| 画像显示「叙述已被剔除，退回统计底座」 | 大模型写的句子没通过事实校验。这是保护机制：宁可给纯统计，也不给编的叙述 |
| 回答标签是「已拦下」 | 模型答了但越界了。展开「查看被拦下的原话」能看到它想说什么，通常说明它说错了具体数字或日期 |
| 有据的问题也被拦下了 | 红线只查「日期 / 数字 / 外文专名 / 引介人名」这些硬事实，措辞不再拦。若是数字被判无据，多半是四舍五入写法（「五十多万」）或口径不对，展开原话核对一下 |
| 回答里的时间不对 | 检查 QQ 号是否填对——它参与 ID 反解 |
| 重建后知识库变空 | 「清空」动作会删掉 kb 目录，需要重新导出 |
| 页面突然打不开 / 插件像是停了 | 改动了插件目录里的文件，宿主会停掉运行时。重新发布一次即可。**导出期间别动插件目录**——已经跑起来的抓取不受影响（它在独立进程组里），但导出编排会中断 |

## 分发前自查：这个包能不能给别人

**这个包不含任何个人信息，可以直接分发。** 真实数据全部落在宿主的
`dataDir`（`raw/`、`kb/`、`state.json`），**不在包内**；包内只有代码、文档、
合成演示数据和自绘图标。

自查已经**脚本化**，不再靠手写关键词扫：

```bash
node tests/privacy-scan.mjs
```

它从本机真实知识库**现算**指纹，再回扫包内每一个文件和 `releases/` 下的每一个 zip。
脚本里**不写死任何个人信息**，所以它能随包分发——别人也能拿它扫自己的安装。
本机没有真实知识库时自动跳过（CI 上跑得动）。

查的维度：

| 维度 | 为什么 |
|---|---|
| 十进制 QQ 号 + 大小端 hex 编码 | 同一号码的不同写法 |
| 完整 cell_id | 说说 ID 本身就是身份 |
| **8 位 owner 前缀** | 说说 ID 前 8 位 hex 就是空间主人 QQ 号的小端编码——**只照抄这一段也等于泄漏号码** |
| 16 位前缀 | owner + 精确时间戳 |
| 说说链接、昵称、地点 | 直接标识 |
| 正文的 4 字中文滑窗 | 真实内容 |
| 聚合数字（赞数、时间戳） | **只提示不拦**——不是身份信息，且极易与代码常量撞车 |
| **微信 wxid（2.0 起）** | 本人账号标识（基名 + 带设备后缀的目录名两种写法）、好友 wxid、动态 ID |
| **包内禁 wxid 字面量（2.0 起）** | **结构性规则，与本机数据无关，永远生效**：插件永远不该硬编码任何人的账号标识符。明显是 `demo` / `example` 这类合成值才放行 |

> **踩过的坑（v1.7.1 修掉）**：v1.3.0 ~ v1.6.2 的文档注释里写着一条**真实说说 ID** 当示例。
> 当时的扫描用的是「带上下文」的关键词（`mood/<前缀>`），
> 而包里的裸 ID 没有 `mood/` 前缀——**整个漏掉了**。
> 教训：扫隐私必须用**裸标识符**，不能用带上下文的模式。
> 现在改掉了，示例换成合成的 `b327e672…`。
>
> **同一类事故第二次（v2.0.0 修掉）**：2.0 的方案文档里写着本机真实 wxid。
> 仓库是公开的，那等于把账号标识公开了。
> 现在回扫范围从「包目录 + 发布 zip」扩到「包目录 + **仓库根目录的说明文档** + 发布 zip」，
> 并且加了一条结构性规则：包内出现 `wxid_xxxxxxxx` 形状的字面量直接判失败。

其它约定：

> 写测试时**不要用真实账号的 cell_id、说说正文、好友昵称**——
> 哪怕只是一个 cell_id，也能反解出你的 QQ 号。
> 包里的测试数据全部是合成的（`moodId()` 按同样的编码规则现场生成）。
>
> `tests/mcp-smoke.mjs` 需要一条真实记录来验证「照原话放行」，
> 所以它**从知识库里现取**，不把原文写死在测试文件里。
>
> `tests/visualizer-static.mjs` 检查「样例数据里没有账号标识」，
> 断言本身**不写死任何具体号码**——写死就等于把真实号码抄进分发包。
> 它用「6–12 位数字串 + ownerUin + dataDir 路径」这类通用判据。
>
> `skills/qq-space-kb-visualizer/` 里的样例年份分布也是合成的
> （8 个年份、26 条），**不是**任何真实账号的分布。
>
> `tests/fixtures/seed-demo.mjs` 里的演示数据也是合成的，
> 界面会打上「演示数据」标记，不会和真实导出混淆。

端到端部分守的是这几条硬规则：

| 断言 | 守的是什么 |
|---|---|
| 需要模型的对话立即返回，不挂在 HTTP 请求上 | 宿主会在请求超时后掐断连接，挂在请求里的模型回合会被一起杀掉 |
| 越界问题也会调模型 | 检索不再是闸门，检索只负责给模型找资料；越界由事实红线兜底 |
| 检索落空时升级到全库速览 | 「我是个什么样的人」这类问法检索不到明细，但全库摊开模型就能答 |
| 模型说不知道时回固定话术 | 固定话术由模型自己说——它手里有全库，它说没有就是没有 |
| Agent 编造内容被事实红线拦下 | 模型答了也要过事实校验 |
| 宿主回 AGENT_UNAVAILABLE 时自动重试 | Mini App 刚启动时问的第一句话不该直接报错 |
| 追问时上下文并入了此前检索到的资料 | 多轮连续性靠显式上下文，不靠模型记忆 |

### 一条贯穿全局的约束

**耗时的事情不能挂在 HTTP 请求里。** 宿主的代理会在请求超时后掐断连接，挂在请求里的
长任务（模型回合、抓取脚本）会被一起杀掉，页面只看到「Failed to fetch」或「浏览器自己关了」。

所以本包里三处耗时操作全部是「登记任务 + 立即返回 + 轮询状态」：

| 操作 | 入口 | 状态查询 |
|---|---|---|
| 导出 | `POST /api/export/start` | `GET /api/state` |
| 人物画像 | `POST /api/profile/build` | `GET /api/state` |
| 对话 | `POST /api/chat` | `GET /api/chat/result?id=…` |

对话永远走后台任务：登记任务、立即返回、前端轮询取结果。
**没有任何一条路径是同步等模型的**——宿主会在请求超时后掐断连接，
挂在请求里的模型回合会被一起杀掉，答案全丢。
