# 组件配方：人生档案 · 年份分布看板

本插件只有一个业务可视化配方。它由 `kb_stats` 的结构化结果驱动，**不自己取数**。

---

## 配方 A：年份分布看板

### 业务问题

「我的 QQ 空间说说是哪几年发的？哪几年数据最密？哪几年只剩回溯痕迹？」

这个问题的答案如果只用文字表达，会退化成一句「2013 到 2020 年，共 26 条」。用户真正想看的是**形状**：哪一年是高峰、哪一年空、哪一年的数据大半是删过又捞回来的。年份构成是结构化、确定性的统计，画出来比读数字快得多。

### 选择规则

| 条件 | 动作 |
|---|---|
| 用户问「覆盖哪些年 / 哪几年最多 / 说说的时间分布 / 知识库整体情况」 | 用本配方，`kind="dashboard"` |
| 用户问某一年具体发生了什么 | **不用本配方**，走业务技能的 `kb_records` + `kb_search`，回文字 |
| 用户问「我是个什么样的人」 | 不用本配方，走 `kb_profile` |
| `yearDistribution` 长度 ≤ 5 | 降级为 `kind="chart"` 的单序列柱状图；再小就直接用文字列表 |
| `yearDistribution` 长度 ≥ 6 | 用本配方的 `kind="dashboard"`，逐年构成走 Chart.js 堆叠柱 |
| `totalRecords` 为 0 | 不出图，走空态 |

**为什么按年份而不是按别的维度切**：时间是这个知识库唯一可靠的排序键——没有时间的记录连年份都进不了分布，而年份是用户唯一能凭记忆核对的维度。

### 必需输入字段

| 字段 | 用途 | 单位 | 缺失处理 |
|---|---|---|---|
| `totalRecords` | KPI：说说总数 | 条 | 缺省 0 |
| `recoveredRecords` | KPI：已删除后恢复 | 条 | 缺省 0 |
| `recoveredBodyMissing` | KPI：正文未能恢复 | 条 | 缺省 0 |
| `recordsWithoutYear` | 脚注：这些记录没有年份，不进分布 | 条 | 缺省 0 |
| `yearFrom` / `yearTo` | KPI：覆盖年份区间 | 年 | 空串则显示「—」 |
| `yearDistribution[]` | 主数据集 | 条 | 空数组走空态 |
| `yearDistribution[].year` | 稳定标识符，下钻用 | 年 | 必填 |
| `yearDistribution[].count` | 柱高 | 条 | 必填 |
| `yearDistribution[].recovered` | 堆叠分段 | 条 | 缺省 0 |
| `yearDistribution[].bodyMissing` | 堆叠分段 | 条 | 缺省 0 |
| `yearDistribution[].withBody` | 校验用（= count − bodyMissing） | 条 | 缺省 0 |

**数据来源**：`kb_stats`（MCP server `life-archive`），本地知识库确定性统计。
**禁止**在组件里重新调业务接口、禁止编造缺失年份、禁止把 `ownerUin` / `persona` / `dataDir` 画进任何组件。

### Widget 形态与语义层级

```
kind="dashboard"，capabilities="resize,sendPrompt"
├─ KPI 行（4 张卡，自上而下最重要）
│   说说总数 · 覆盖年份 · 已删除后恢复 · 正文未能恢复
├─ 主图：逐年构成（Chart.js 堆叠柱，3 个分段）
│   现存有正文 / 回溯有正文 / 回溯无正文
├─ 紧凑明细表：年份 | 条数 | 回溯 | 正文缺失
└─ 行动条：2 个追问按钮
```

**语义层级**：先看总量与年份跨度，再看形状（哪年高、哪年空），最后看构成（多少是回溯的）。

**分段配色**：`--mw-chart-1`（现存有正文）→ `--mw-chart-2`（回溯有正文）→ `--mw-chart-3`（回溯无正文）。
这三个是**语义顺序**不是好看顺序：读者一眼扫过去要能看出「回溯那部分在变深」。深浅由宿主主题桥决定，代码里不要写死色值。

### 本地交互（留在前端，不回传模型）

| 交互 | 行为 |
|---|---|
| 悬停柱体 | 显示该年「共 N 条 · 回溯 M 条 · 正文缺失 K 条」 |
| 悬停表格行 | 同上，行高亮 |
| 表格按条数排序 | 表头可点击，本地切换升/降序，不发消息 |
| 明细表滚动 | 超过 10 行时表格区域内部滚动，KPI 与图表不跟着动 |

**过滤、排序、切换视图一律留本地。** 每点一下就回传模型是交互垃圾。

### 追问（sendPrompt）及其载荷

只在两处发消息，都是「用户可能真的想问」的场景：

| 触发点 | 文本 | selectedData | userIntent |
|---|---|---|---|
| 点击某年柱体 | 「列出 2017 年我发过的说说。」 | `{ year, count, recovered, bodyMissing, withBody }` | 列出该年份的全部说说 |
| 点击表格行 | 同上 | 同上 | 列出该年份的全部说说 |
| 行动条「哪一年最密」 | 「我的说说在哪一年最密集？那一年大概在忙什么？」 | `{ year, count, ... }`（最密那年） | 分析数据最密集的年份 |
| 行动条「回溯集中在哪几年」 | 「我删掉又捞回来的说说集中在哪几年？说明什么？」 | `{ years: [...], recoveredTotal }` | 分析回溯记录的年份分布 |

**载荷纪律**：`selectedData` 只放 `yearDistribution` 里真实存在的字段与值。
不放 QQ 号、不放 `dataDir` 路径、不放原始报错、不放任何凭证。

**语言**：`text` 与 `userIntent` 都用中文（跟随对话语言）。这是硬要求，不是风格偏好。

### 各状态的表现

| 状态 | 表现 |
|---|---|
| **正常** | KPI 四卡 + 堆叠柱 + 明细表 + 行动条，全部由 `kb_stats` 的真实值填充 |
| **加载中** | 先出结构：KPI 卡片数值显示 `--`，图表容器显示 `--mw-surface-muted` 底色，明细表空行占位；不出图例，不画空柱 |
| **空** | `totalRecords` 为 0 或 `yearDistribution` 为空：保留 KPI 与图表框架，居中一行「知识库还没有数据，先导出说说并建库」；**不渲染行动条**（没有可问的对象），**不出 sendPrompt 按钮** |
| **错误** | `kb_stats` 报错或结构非法：保留布局，内联一行「知识库统计没取到，先回文字回答」；不展示半截数据，不把原始报错贴给用户 |
| **权限/鉴权** | 本技能不发起鉴权型业务调用。宿主未授予 MCP 权限时，**直接走文字兜底**，不出图、不出按钮 |
| **文字兜底** | 不出图时的完整替代：按年份列出「年份 · 条数 · 回溯 · 正文缺失」的 Markdown 表 + 一句结论 |

### 什么时候不出图

- 数据不可视：只有一两个数字，直接说。
- 用户明确要纯文字。
- 业务技能的接地校验判定「知识库里没有这条」——这时不能画图，要回固定话术。
  **可视化不是绕过接地规则的出口。** 画出来的每个数字都来自知识库真实统计，不是模型生成的。
