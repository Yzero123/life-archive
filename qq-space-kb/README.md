# QQ 空间说说知识库 · Mini App

把你的 QQ 空间历史说说变成一个会说话、但**只依据你的真实记录作答**的聊天 bot。

---

## 它做什么

| 阶段 | 动作 | 结果 |
|---|---|---|
| ① 导出 | 打开 QQ 空间登录页，你用手机 QQ 扫码；Agent 驱动导出工具抓取全量说说 | `messages.json`（含评论/点赞/定位）+ 归档库快照（含已删除后恢复的内容） |
| ② 建库 | 两路数据按说说 ID 合并去重；切明细块与年度画像块 | 可检索的知识库 + 检索索引 |
| ③ 人物画像 | 建库时自动生成统计底座；可再让大模型润色成有性格的叙述 | 一份「我是谁」底色，注入之后每一轮对话 |
| ④ 对话 | 先检索，检索不到直接回固定话术；检索到才让模型基于资料作答 | 有依据的回答，附来源 |

**核心约束：回答必须有知识库依据。** 查不到就说「当时的我还不知道这是什么意思」，不编造。

人物画像不是装饰。bot 只复述检索结果会显得「蠢」：问「我是个什么样的人」时它没有可复述的记录。
画像让 bot 知道自己是谁，于是泛化类问题有依据可依，口气也才像同一个人。

## 安装

本包是标准 MiniMax Plugin（含 `miniapp.json` 声明与页面 / Node 两份运行载荷），有两种装法：

### 方式 A：交给 Agent 装（最省事）

把本包目录或 ZIP 交给 MiniMax Code 里的 Agent，说一句：

> 这是个成品 Mini App 包，帮我安装并打开。

Agent 会按成品包流程完成校验、发布和启动。

### 方式 B：手动放到插件目录

```bash
# 把整个插件目录（含隐藏的 .minimax-plugin）复制到插件目录，不要带外层作者目录
cp -R qq-space-kb ~/.minimax/plugins/qq-space-kb
```

然后**重启 MiniMax Code**，在插件列表里确认「QQ 空间说说知识库」已识别并启用。

### 前提条件

- MiniMax Code 桌面端（macOS / Windows），**本地会话**。云端、SSH、Remote Control 会话不会启动本机 Mini App。
- 插件详情里保持 **Agent 调用（session.run）** 打开。导出和对话都要用它。
- 无需预装任何依赖：Node 侧只用内置模块，导出工具由 Agent 在运行过程中自动 clone 和安装。

## 怎么用

### 三步走

1. **打开 Mini App**
   在 MCode 里打开「QQ 空间说说知识库」。页面上半部分是导出与建库，下半部分是对话。

2. **填 QQ 号 → 点「开始导出」**
   - 填你的 QQ 号。用于校验记录归属，并从说说 ID 反解原始发布时间，**强烈建议填**。
   - Agent 会打开 QQ 空间登录页，**用手机 QQ 扫码**完成登录。这一步只能你本人做。
   - 抓取过程慢速进行（每页间隔 20 秒，每 10 页休息 3 分钟），降低风控。
   - 期间 Agent 请求执行命令时，页面会出现授权卡片，点「允许一次」继续。
   - ⚠️ 抓取期间不要切换 QQ 客户端账号，否则有账号冻结风险。
   - **浏览器被关掉就是你要中止**，不会自动重开。断点会留着，再点一次「开始导出」从断点续上。

3. **点「构建知识库」→「生成人物画像」→「开始对话」**
   - 页面会显示说说总数、其中已删除后恢复的条数、覆盖年份区间、知识块数量。
   - **建库的同时就会自动生成一份「统计底座」画像**（纯统计，零成本零编造），
     对话立刻就有底色可用；再点一次「生成人物画像」，让大模型把它润色成
     有时间线、有社交圈、有性格的叙述。这一步在后台跑，页面会显示进度。
   - 建议先填「人设」，决定 bot 用什么语气说话。
   - 直接在下方对话框提问。

### 提问示例

| 问题 | 预期 |
|---|---|
| 2015 年我在忙什么 | 命中年度画像，给出有依据的回答 |
| 我有没有提过静安寺 | 命中明细块，引用具体那条 |
| 我是个什么样的人 | 走人物画像，给出性格、说话方式和时间线的概括 |
| 那几年我过得怎么样 | 同上，按年度把那段日子串起来 |
| 特斯拉 Cybertruck 续航多少 | **「当时的我还不知道这是什么意思」** |
| 我当年买过特斯拉吗 | **「当时的我还不知道这是什么意思」**（带「我」也不等于泛化问法） |

> 模型回合要几十秒。问完之后对话区会显示「正在想…」，等一会儿就出结果。
> 这是后台任务在跑，页面不会卡死；刷新页面也不会丢——结果存在服务侧。

### 回答上的标签

每条 bot 回复左上角都会标出它属于哪种情况，别把两种失败混在一起看：

| 标签 | 含义 |
|---|---|
| 当时的我 | 有知识库依据，展开「依据 N 条知识库记录」能看到出处 |
| 当时的我 · 知识库里没有这条 | 检索没命中，**根本没有调用模型**，不存在编造机会 |
| 当时的我 · 回答没落在资料里，已拦下 | 模型答了但内容重合度不够，答案被丢弃 |
| 当时的我 · 回答含资料外的事实，已拦下 | 模型答了但出现了资料里没有的日期 / 数字，答案被丢弃 |

后两种可以展开「查看被拦下的原话（未采用）」，看到模型本来想说什么。

### 权限卡片

Agent 执行浏览器操作、跑命令行时需要你确认，页面会弹出授权卡片。点「允许一次」或「拒绝」，卡片会消失。拒绝不会中断整体流程，Agent 会收到「已拒绝」并自行决定下一步。

对话环节不会请求任何工具权限——模型只能看本轮给它的资料。

## 回答是怎么被约束的

这是本 Mini App 最重要的部分，三道闸门：

### 1. 检索闸门

对话先做 BM25 检索（中文按字符二元组切分，无需分词器）。命中分数过低、或查询词覆盖率不足时，**根本不调用模型**，直接返回固定话术。这保证「不知道」的时候没有任何编造的机会。

问句会先做**问法词归一化**：「什么」「怎么」「我」「在」这类问法词不进检索，否则「2018 年我在忙什么」会被「我在忙」稀释掉分数，把明明存在的年份记录判成查不到。归一化后若只剩一个年份，就按年份直接定位那一年的记录。

注意这条放行是**有条件的**：只有归一化后**只剩**年份才按年份定位。「2019 年特斯拉续航多少」还带着别的内容，照样查不到，直接回固定话术。

**泛化问法走另一条路。**「我是个什么样的人」剥掉问法词只剩「个什么样人」这种没有实义的组合，BM25 命中不了任何一条具体说说——问的是人，不是事。但它的答案就在人物画像里：画像同样是从全量说说归纳出来的，属于知识库，只是走的不是逐条检索这条路。所以这类问法被单独识别出来，直接放行给模型。

判定刻意保守，必须同时出现「自指」和「性格/生活类」特征：「我是个什么样的人」「那几年我过得怎么样」算，「我昨天吃饭了吗」「我当年买过特斯拉吗」不算——带个「我」不等于泛化问法，后者照旧回固定话术，**不会**因为画像存在就放行。

### 2. 提示闸门

命中后，把「知识库资料」和「你是谁」（人物画像）两段一起交给模型，并明确要求：只能用资料里的信息、必须用过去时态、不知道就说不知道、不输出「根据知识库」这类元叙述、只输出最终回答本身。

每个问题都开一个**独立会话**，上一轮被判为编造的原话不会留在会话历史里污染下一轮。连续性靠显式并入的知识库上下文维持（本轮命中的块 + 此前检索到的块，上限 12 块），不靠模型记忆。

### 3. 接地校验闸门

模型回答后，Node 侧再校验一次，任一不达标就**丢掉模型答案**，改用固定话术：

| 检查 | 规则 | 性质 |
|---|---|---|
| 日期 | 答案里的年 / 年月 / 年月日 / 月 / 日，必须能在资料里找到对应的那一天 | 硬红线 |
| 数字 | 答案里量级 ≥ 10 的数字（含中文数字，如「一万」）必须能在资料里找到 | 硬红线 |
| 外文专名 | 答案里含大写字母的外文词（`iPhone`、`Instagram`、`Tesla`）必须在资料里出现过 | 硬红线 |
| 引介人名 | 「认识了一个叫小美的朋友」——小美得是资料里真有其人 | 硬红线 |
| 内容词重合度 | 答案的内容词二元组与资料的重合度 ≥ 27% | 兜底 |

**硬红线负责「不许编造具体事实」，重合度只兜「整段都在编」的情况。** 这个分工很重要：
中文口语回答里虚词二元组（「那帮人」「倒是没少」）天然不重合，阈值定太高会把
**有据可依**的回答误杀成固定话术——那看起来像「知识库里没有」，其实是有。
实测重合度分布：照资料原话转述 0.73，有据的口语转述 0.33，掺假的经历 0.17，纯编造 0.04。

日期检查做了**写法归一化**：资料里存的是 `2015-11-20`，模型常写成「2015 年 11 月 20 日」「2015年11月20号」，这些认作同一件事，不会误杀合规回答；而「2015 年 11 月 21 日」这种真正对不上的会被拦下。

数字检查会先剥掉 URL 和 `cell_id` 这类长 hex 串再比对。不剥的话，
`cell_id`「…3c0500」里的「500」会被当成资料里出现过的数字，
于是「我欠了同学 500 块」这种编造能蒙混过关——红线就漏了。

人设是用户自己写的，属于可信事实，也纳入接地上下文——免得模型复述人设里的年份时被误判成编造。

> 措辞级校验有天花板：中文没有分词器，「那帮人」和「小美」这类短语的可靠性有限。
> 所以除了让模型**照资料原话回答**（提示词里明确要求），画像里也直接带上各年的代表原文，
> 让它有原话可照——这既更像本人，接地校验也更有据。
> 仍然拦不住的是「大量真实转述里夹一句资料外的话」这种形态。

### 人物画像是怎么来的

画像分两层，**大模型只做润色，不负责事实**：

| 层 | 来源 | 作用 |
|---|---|---|
| 统计底座 | 纯确定性统计：跨度、年份分布、最活跃时期、常去地点、互动最多的人、反复话题、表达习惯、互动总量、最受欢迎一条、**各年代表原文** | 永远可用，零成本，零编造 |
| 大模型叙述 | 读完全量说说后写的时间线 / 社交 / 说话方式 / 性格 | 让 bot 有「像人」的叙述，而不是干巴巴的统计表 |

大模型写出的每一句都要过一遍事实校验（年份必须落在记录年份内、日期必须对得上、数字必须有出处）。过不了校验的句子直接剔除；站得住的句子不足 3 句、或占比低于一半，就**整段退回统计底座**。

所以画像永远不会是编的：最差情况是回到一份纯统计表。

**统计底座是建库时自动生成的**，不用等大模型——点一次「构建知识库」就有。
这一点不是可有可无：对话里少了人物底色，接地校验会因为措辞命中率不够，
把本来有据可依的回答误杀成固定话术，用户看到的就是「这功能答不出来」。

底座里特意带了**各年代表原文**（每年一条点赞最多的）。两个用处：
模型照着那一年的原话回答才像本人；接地校验靠的正是措辞重合，
有原话可照，校验才有据。

## 时间是怎么来的

QQ 空间标准说说 ID 的前 16 位十六进制里藏着两个小端 u32：

```
b327e672 e295585b
└─ 空间主人QQ号 ─┘ └─ 原始发布时间戳 ─┘
```

所以即使一条说说的正文只在「点赞/评论残留」里还存在，**发布时间依然能精确还原**，时间轴不会因为删除而断裂。

每条记录都带时间精度标记，界面和知识块里都写得很清楚：

| 标记 | 含义 |
|---|---|
| 精确 | 源数据直接给出的发布时间 |
| 由说说ID反解 | 由说说 ID 还原得出 |
| 互动时间近似 | 只能拿到互动发生时间，是近似值 |
| 未知 | 完全不可考，不会编一个日期（仍会入库，正文照常可检索） |

## 导出工具

Agent 会自动准备下列工具之一，你也可以提前装好：

| 工具 | 仓库 | 特点 |
|---|---|---|
| get-qzone-history（首选） | github.com/Christina-zhou/get-qzone-history | Playwright 驱动真实浏览器扫码登录；字段干净；带断点续跑；macOS 下需把默认的 Windows `browserPath` 改成 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` |
| QQ-Zone-Restore-Archive | github.com/xiaosu19/QQ-Zone-Restore-Archive | Rust/Tauri 桌面端；**能从互动残留恢复已删除的说说**；库里是 SQLite，Agent 会转成 JSON |

两个都装的话效果最好：前者字段全（评论正文、点赞用户、定位），后者能捞回删掉的内容。

> 全量抓取耗时以小时计（默认 200 页 × 每页 20 秒 + 分段休息）。

### 导出是怎么被约束的

抓取脚本**不是**由 Agent 即兴写命令启动的。点「开始导出」时，Mini App 会把一个受控运行器写进数据目录（`export/qq_export_runner.py`），Agent 只需要调用它。运行器只做三件事：

| 做什么 | 为什么 |
|---|---|
| 保证工具就位（缺就 clone，依赖缺就装） | Agent 不需要自己拼装环境 |
| **把抓取脚本挂进独立进程组**（`start_new_session=True`） | 抓取要等扫码、以小时计。挂在一次前台工具调用里，工具调用一到时限就会连带把进程和浏览器杀掉——用户看到的就是「页面还没加载完就自动关闭」 |
| 把状态写进 `status.json` | Agent 轮询这个文件汇报进度，不用盯着长命令 |

**绝不自动重开浏览器。** 浏览器被关闭 = 用户主动中止，这时候自动重启只会不停弹窗、每次都要重新扫码。所以运行器里没有任何重跑循环：脚本退出就是退出，状态如实写进 `status.json`。断点留在 `result/` 目录里，用户再点一次「开始导出」就从断点续上。

导出指令里也把这条写成了铁律，并明确禁止 Agent 写 supervisor / 守护循环。

### 已删除的说说怎么回溯

按优先级找数据源，找不到就如实说明，**绝不编造**：

| 顺序 | 数据源 | 说明 |
|---|---|---|
| 1 | 本机归档库 | QQ-Zone-Restore-Archive 的 SQLite。macOS 在 `~/Library/Application Support/top.ehre.qzonearchive/qzone-archive.sqlite3`；找不到就全盘搜 `qzone-archive*.sqlite3` |
| 2 | 互动中心的历史消息 | 已删除但仍被人点赞评论的说说，会在历史消息卡片里留下痕迹：卡片带 `/mood/<cell_id>` 链接，而这个 cell_id 不在说说列表里。接口是 `user.qzone.qq.com/proxy/domain/ic2.qzone.qq.com/cgi-bin/feeds/feeds2_html_pav_all`（`count` 必须 ≤ 30） |
| 3 | 都没有 | 写一个空的 `{"dynamics": [], "feeds": []}`，页面显示「已删除后恢复 0」并**说明原因** |

页面统计下方的提示条会写清楚为什么是 0（例如「本机既没有 QQ 客户端缓存，也没有归档库」）。
这是数据源缺失，不是功能坏了——**没有被点赞评论过、已被服务端彻底清除的内容无法恢复**。

#### 正文没捞回来，也照样算一条

已删除的说说在互动卡片里常常只剩时间戳和 `cell_id`，正文预览未必还在。
但只要有 `cell_id`，发布时间就能由 ID 反解出来（`mood_cell_id_published_at`），
于是「发过、什么时候发、被谁赞过/评论过」本身就是能确证的事实——**这些条目会照常进知识库**，
正文位置写明「（这条说说已删除，正文未能恢复）」，模型被明确禁止去猜原文。

早期版本在「合并记录」和「切成知识块」两处都按「有没有正文」过滤，
结果明明捞到了 3 个 `cell_id`，界面却一直显示「已删除后恢复 0」。现在两处都不再丢弃这类记录。

#### 别人的动态不算「我的已删除说说」

互动卡片里混着「我评论过的别人的动态」。这类内容**本来就不在「我的说说列表」里**，
所以「历史消息有、说说列表没有」这个差集并不能直接当成「我已删除的说说」。

区分办法在 ID 里：QQ 空间标准说说 ID 的**前 8 位十六进制（小端 u32）就是作者 QQ 号**。
不是本人的就丢掉——收进来的话，bot 会声称自己发过根本没发过的内容，这比漏回溯一条严重得多。

同理，卡片上的 `data-time` 是**互动时间**而不是发布时间。
落盘时标上 `published_from: "interaction"`，真正的发布时间由 ID 反解；
反解不了就如实标成「互动时间近似」，不冒充精确时间。

#### 现成探针（实测可用）

`tools/qzone_feed_recover.js` 是**已经跑通**的回溯探针，直接用就行，不用从零写。
它把这几个坑都处理了：没正文的条目也落盘、按作者过滤、每页增量落盘、
请求按需发（少打请求避开 WAF）、登录判定看 `p_skey` 而不是残留的 `uin`。

```bash
# 依赖：playwright（用导出工具自己的 node_modules）+ 系统 Chrome
cd <导出工具目录>
NODE_PATH=<导出工具目录>/node_modules node <包目录>/tools/qzone_feed_recover.js \
  --target-qq <QQ号> \
  --shuoshuo <导出产物 messages.json> \
  --out <数据目录>/raw/qzone_archive.json \
  --work-dir /tmp/qq-space-export-work --login-timeout 900 --max-pages 20
```

跑起来会弹出浏览器窗口，**需要你扫一次码并在手机 QQ 上点「确认登录」**
（`uin` / `p_skey` 是会话 cookie，浏览器一关就没了）。
跑完把 `raw/qzone_archive.json` 放好，再点「构建知识库」即可。

> 回溯探针要自己开一个浏览器窗口，并且**需要你再扫一次码**：
> QQ 空间的 `uin` / `p_skey` 是**会话 cookie**，浏览器一关就没了，持久化的 profile 里留不住。
> 而且历史消息接口要的是**桌面端**会话（桌面首页里的 `g_qzonetoken`），
> 导出用的移动端登录态不能直接给探针复用。
>
> 回溯还容易被腾讯 WAF 限流（HTTP 501 + `waf.tencent.com` 页面）——请求太密就会触发。
> 看到这个就等 30 秒以上再重试，翻页之间留 3–5 秒；一次回溯别反复重跑，跑得越勤冷却越久。
> 探针**每翻一页就落一次盘**，中途被拦掉时已拿到的卡片不会跟着一起丢。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面提示「未授予 Agent 调用权限」 | 插件详情里把「Agent 调用（session.run）」打开 |
| 导出卡在登录 | 需要你本人扫码，Agent 无法代替 |
| 浏览器被关掉了、页面自己又弹出来 | 旧版本的自动重跑。**当前版本不会**：浏览器被关 = 你中止了，不会自动重开。再点一次「开始导出」从断点续跑 |
| 页面还没加载完浏览器就自己关了 | 旧版本把抓取挂在一次前台工具调用里，工具调用到时限就把浏览器一起杀了。当前版本把抓取挂进独立进程组，不会被连带关闭 |
| 导出被风控提示「使用人数过多」 | 调大间隔（`--page-wait-ms 20000 --segment-pause-ms 180000`），换个时间段再试 |
| 说说数明显偏少 | 归档库的深度扫描没跑完，或接口不再返回更早的数据；**没有被点赞评论过、已被服务端彻底清除的内容无法恢复**。页面会写明这次为什么是 0 |
| 回答总是「当时的我还不知道这是什么意思」 | 知识库是空的或检索没命中。先看统计里的说说总数；换个更贴近原话的问法 |
| 问「我是个什么样的人」也回固定话术 | 泛化问法走画像通道。**建库后就有统计底座**，正常不该发生；先确认知识库非空、统计底座已生成 |
| 画像显示「叙述已被剔除，退回统计底座」 | 大模型写的句子没通过事实校验。这是保护机制：宁可给纯统计，也不给编的叙述 |
| 回答标签是「已拦下」 | 模型答了但越界了。展开「查看被拦下的原话」能看到它想说什么，通常说明知识库缺这条信息 |
| 有据的问题也被拦下了 | 措辞级校验有天花板，中文口语的虚词天然拉低重合度。展开原话看它到底说了什么：如果内容确实有出处，那是误杀，把问题换个更贴近原话的问法或先补上人物画像再试 |
| 回答里的时间不对 | 检查 QQ 号是否填对——它参与 ID 反解 |
| 重建后知识库变空 | 「清空」动作会删掉 kb 目录，需要重新导出 |
| 页面突然打不开 / 插件像是停了 | 改动了插件目录里的文件，宿主会停掉运行时。重新发布一次即可。**导出期间别动插件目录**——已经跑起来的抓取不受影响（它在独立进程组里），但导出编排会中断 |

端到端部分守的是这几条硬规则：

| 断言 | 守的是什么 |
|---|---|
| 需要模型的对话立即返回，不挂在 HTTP 请求上 | 宿主会在请求超时后掐断连接，挂在请求里的模型回合会被一起杀掉 |
| 未命中不调用 Agent | 「不知道」时不存在编造机会 |
| 未命中是同步返回的 | 闸门拦下就当场给固定话术，不占用后台任务 |
| 泛化问题不再落固定话术 / 泛化路由不放行越界问题 | 画像通道只对性格类问法开，不放松越界红线 |
| Agent 编造内容被接地校验拦下 | 模型答了也要过事实校验 |
| 追问时上下文并入了此前检索到的资料 | 多轮连续性靠显式上下文，不靠模型记忆 |

### 一条贯穿全局的约束

**耗时的事情不能挂在 HTTP 请求里。** 宿主的代理会在请求超时后掐断连接，挂在请求里的
长任务（模型回合、抓取脚本）会被一起杀掉，页面只看到「Failed to fetch」或「浏览器自己关了」。

所以本包里三处耗时操作全部是「登记任务 + 立即返回 + 轮询状态」：

| 操作 | 入口 | 状态查询 |
|---|---|---|
| 导出 | `POST /api/export/start` | `GET /api/state` |
| 人物画像 | `POST /api/profile/build` | `GET /api/state` |
| 对话 | `POST /api/chat` | `GET /api/chat/result?id=…` |

唯一同步返回的是检索闸门直接拦下的情况——那本来就该当场给答案。
