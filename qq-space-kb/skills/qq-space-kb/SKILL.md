# QQ 空间说说知识库

把用户的 QQ 空间说说（**含已删除后恢复的**）变成可检索、可对话的知识库。

## 这个技能的核心分工

| 谁 | 干什么 | 为什么 |
|---|---|---|
| MCP 工具 | 检索、统计、画像、接地校验 | 确定性计算，代码说了算，**不调大模型** |
| 你（Agent） | 用检索到的原文组织语言 | 措辞生成需要模型 |

**接地校验放在代码里，不放在提示词里。** 提示词会漏，校验器不会。

## 工具一览（MCP server: `qq-space-kb`）

| 工具 | 作用 | 关键返回 |
|---|---|---|
| `kb_stats` | 总体统计 | `totalRecords` `recoveredRecords` `yearFrom/yearTo` `hasProfile` `persona` |
| `kb_search` | 按问题检索 | `confident` `hits[].text` `profileText` `persona` |
| `kb_records` | 盘点式筛选 | `records[]`（时间/正文/地点/点赞/评论/链接） |
| `kb_profile` | 人物画像 | `narrative` `facts` `yearlySummaries` |
| `kb_ground_check` | 接地校验 | `ok` `ratio` `factsOk` `reason` |

## 回答问题的标准流程

### 第 1 步：检索

调用 `kb_search`，`query` 填用户原话。

### 第 2 步：检索没命中怎么办

**检索只是帮你找资料，不是「答不答得出来」的判据。** 检索没命中≠知识库里没有。

- `confident: true` → 直接进第 3 步。
- `confident: false` → 按顺序试：
  1. **问的是人**（自指类问题，如「我是个什么样的人」「那几年我过得怎么样」）：
     答案在 `profileText` 里，照常往下走。
  2. **问的是事但检索没命中**：用 `kb_records` 把全库拉出来看一遍
     （`kb_records` 不带过滤条件就是全量），从里面找有没有能回答的记录。
     **找到了就照常回答**——不要因为「检索没命中」就说不知道。
  3. 全库翻完确实没有 → 回固定话术，一句都不要多说：

     > 当时的我还不知道这是什么意思

     这条路径上不要解释「知识库里没有」、不要给建议、不要猜。

### 第 3 步：组织回答

可用素材只有四样：`hits[].text`（检索命中的知识库原文）、`kb_records` 拉到的全库原文、`profileText`（人物画像）、`persona`（用户自己写的人设）。

规则：

1. **只用这四样**。一个日期、一个金额、一个外文专名、一个朋友的名字，都必须能在素材里找到。
2. **尽量照原话说**。资料写「周六爬山」就别改成「周末去爬了个山」——换过说法既不像本人，也容易被判成没落在资料里。
3. **过去时态**。资料是过去留下的记录。
4. **短**。1–3 句，像发朋友圈。
5. **不说教、不自称 AI、不输出「根据资料」这类元叙述**。
6. 标了「正文未能恢复」的说说，只能说它发过、什么时候发、被谁互动过，**不要猜它当时写了什么**。
7. `timeSourceLabel` 是「互动时间近似」的记录，时间要说明是推测，不能当精确时间讲。
8. **条数、数量照 `kb_stats` / 年度小结里的数字抄**，不要自己数记录条数——数出来的会错，错的会被校验拦下。

### 第 4 步：校验（必做）

把准备回答的文本丢进 `kb_ground_check`：

```
kb_ground_check({ answer: "<你的回答原文>", context: "<你用的素材原文>" })
```

- `ok: true` → 正常回答。
- `ok: false` → **改成固定话术**，不要把被判不合格的原话发给用户。`reason` 会告诉你是哪种问题：
  - `ungrounded_factual_claim` → 编了日期 / 金额 / 模糊量 / 外文专名 / 人名

  `ratio`（措辞重合度）**只作参考**，不是拒答条件——中文口语的虚词天然拉低重合度，
  拿它当闸门会把有据的回答误杀成「不知道」。

校验不过时最多重写一次；再不过就回固定话术。

## 知识库是空的怎么办

`kb_stats` 显示 `totalRecords: 0`，说明还没导出。按下面流程走（**必须由用户本人扫码，不能代劳**）：

1. 打开 Mini App「QQ 空间说说知识库」，填 QQ 号，点导出。
2. 浏览器会弹出 QQ 登录页 → **让用户自己扫码 + 手机 QQ 确认**。不要尝试代填密码或绕过验证。
3. 导出是**后台任务**：运行器挂在独立进程组里，浏览器被用户关掉就停止。不要反复重启它，否则浏览器会反复弹给用户。
4. 导出结束后点「建立知识库」，系统会自动生成一份统计底座画像（不调模型，不编造）。

**回溯已删除说说**：包内自带探针 `tools/qzone_feed_recover.js`，走归档库 + 互动中心历史消息两个数据源，差集里带 `cell_id` 的就是删过又留下的痕迹。

两条铁律：

- 探针**只取本人**的动态。`cell_id` 前 8 位就是作者 QQ 号，不匹配的一律丢弃——把别人的动态当成本人的，比漏一条严重得多。
- 腾讯 WAF 会限流（HTTP 501）。被拦就退避 30 秒再试，别硬冲。

## 边界

- 只能处理用户本人或已授权的数据。
- 不伪造登录态，不绕过风控。
- 措辞级接地校验有天花板：拦不住「大量真实转述里夹一句资料外的话」。所以第 3 步的纪律比阈值更重要。
- 知识库里的内容只在本机，`dataDir` 下，不外传。

## 组合说明：什么时候交给可视化分支

本技能**始终是一个完整的文字版业务工作流**。问什么都能用文字答完，不依赖任何可视化。

只有在下面这种情形下，才把结果交给同插件的
`qq-space-kb:qq-space-kb-visualizer` 技能（运行时限定名）：

| 情形 | 归属 |
|---|---|
| 问年份分布、哪一年最密、回溯集中在哪几年、整体覆盖情况 | 先调 `kb_stats`，再交给可视化技能出看板 |
| 问某一年具体发生了什么 | **留在本技能**：用 `kb_records` + `kb_search` 回文字 |
| 问「我是个什么样的人」 | **留在本技能**：用 `kb_profile` 回文字 |
| 问一条具体的说说 | **留在本技能**：用 `kb_search` 引用原文 |
| 接地校验判定「知识库里没有这条」 | **留在本技能**：回固定话术，**不配图** |

两条纪律：

1. **先出业务结果，再决定要不要图。** 可视化技能不自己取数，它只消费 `kb_stats` 已经算好的统计。
2. **图不是绕过接地规则的出口。** 判定为「知识库里没有」时，答案就是那句话，不画任何东西。
